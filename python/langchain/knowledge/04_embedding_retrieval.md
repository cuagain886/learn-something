# 04 · 嵌入与检索原理 ⭐

> 向量检索是 RAG 的数学基础。理解嵌入模型的工作原理、相似度度量和索引结构。

---

## 1. 文本嵌入原理

### 什么是嵌入

把文本映射到高维向量空间中的一个点：

```
"Python 是一门编程语言"  →  [0.12, -0.34, 0.56, ..., 0.78]  (1536 维)
"Java 也是编程语言"      →  [0.11, -0.32, 0.54, ..., 0.77]  (相近的向量)
"今天天气不错"           →  [0.89, 0.23, -0.67, ..., 0.12]  (远离的向量)
```

### 嵌入模型的训练

1. **对比学习**：让相似文本的向量靠近，不相似的远离
2. **训练数据**：(query, positive_doc, negative_doc) 三元组
3. **模型结构**：通常是 Transformer encoder（如 BERT 变体）

### Bi-Encoder vs Cross-Encoder

```
Bi-Encoder（双塔模型）：
  Query → Encoder → vec_q  ─┐
                              ├─ cosine_similarity(vec_q, vec_d) → 分数
  Doc → Encoder → vec_d    ─┘
  优点：可以预计算文档向量，检索快
  缺点：精度略低

Cross-Encoder（交叉编码器）：
  [Query; Doc] → Encoder → 分数
  优点：精度高（query 和 doc 之间有注意力交互）
  缺点：不能预计算，每次都要重新编码，慢
  用途：重排序阶段
```

## 2. 相似度度量

### 余弦相似度（最常用）

```
cosine(A, B) = (A · B) / (|A| × |B|)

范围：[-1, 1]
1 = 完全相同方向
0 = 正交（无关）
-1 = 完全相反

优点：不受向量长度影响，只看方向
```

### 欧氏距离

```
L2(A, B) = √(Σ(ai - bi)²)

范围：[0, +∞)
越小越相似

注意：受向量长度影响，通常需要归一化
```

### 点积（内积）

```
dot(A, B) = Σ(ai × bi)

如果向量已归一化，点积 = 余弦相似度
OpenAI 的嵌入已经归一化，三种度量等价
```

### 选择建议

| 度量 | 适用场景 | 常用于 |
|------|---------|-------|
| 余弦相似度 | 通用（推荐默认） | 大多数向量库 |
| 欧氏距离 | 需要考虑向量大小 | FAISS 默认 |
| 点积 | 已归一化的向量 | Pinecone |

## 3. 向量索引结构

### 暴力搜索（Flat）

```
遍历所有向量，计算相似度，取 Top-K
时间：O(n × d)  n=向量数, d=维度
精确但慢，只适合小规模（<10万）
```

### IVF（倒排文件索引）

```
1. 用 K-Means 把向量分成 nlist 个簇
2. 每个簇有一个中心向量
3. 查询时：先找最近的 nprobe 个簇，只在这些簇内搜索

时间：O(nprobe × n/nlist × d)
参数：nlist=100-1000, nprobe=1-100
精度-速度权衡：nprobe 越大越准但越慢
```

### HNSW（分层导航小世界图）

```
构建多层图：
  Layer 2:  ○───────────○           （稀疏，跳跃远）
  Layer 1:  ○───○───○───○───○       （中等密度）
  Layer 0:  ○─○─○─○─○─○─○─○─○─○   （最密集，所有向量）

查询从最高层开始，逐层向下，每层贪心搜索最近邻
类似跳表，时间 O(log n × d)

优点：查询极快，召回率高
缺点：内存占用大，构建慢
```

### PQ（乘积量化）

```
把 d 维向量分成 m 段，每段用码本量化
极大压缩向量存储（128 维 float32 → 几十字节）

适用：超大规模（10亿+），可以牺牲精度换空间
```

### 索引选择指南

| 数据规模 | 推荐索引 | 说明 |
|---------|---------|------|
| <10 万 | Flat | 精确搜索，够快 |
| 10-100 万 | HNSW | 速度和精度最佳平衡 |
| 100-1000 万 | IVF+HNSW | 分区 + 图索引 |
| >1000 万 | IVF+PQ | 压缩存储 |

## 4. 嵌入模型选择

### OpenAI Embeddings

```
text-embedding-3-small: 1536 维, $0.02/1M tokens
text-embedding-3-large: 3072 维, $0.13/1M tokens

特点：
- 支持 dimensions 参数裁剪维度（如 3072 → 256）
- 已经 L2 归一化
- 多语言支持好
```

### 开源嵌入模型

```
BGE (BAAI)：中英文效果好，可本地部署
E5：微软，指令微调版本效果出色
GTE：阿里，多语言
Jina：长文本支持（8192 tokens）
Nomic：开源、支持长上下文
```

### 嵌入维度的影响

```
维度越高：
  ✓ 表达能力越强
  ✗ 存储和计算成本越高
  ✗ 稀疏性增加（维度灾难）

实践建议：
  - 大多数场景 768-1536 维足够
  - 如果存储受限，可以用降维技术（PCA、Matryoshka）
```

## 5. 检索优化技术

### Matryoshka Embeddings（套娃嵌入）

```
一个模型，生成不同维度的嵌入，且前 N 维自身就是有效嵌入：
[d1, d2, ..., d256] → 有效
[d1, d2, ..., d512] → 更好
[d1, d2, ..., d1536] → 最好

OpenAI text-embedding-3 系列支持此特性
用法：先用低维快速过滤，再用高维精排
```

### Late Interaction（ColBERT）

```
传统：query → 1个向量, doc → 1个向量
ColBERT：query → N个token向量, doc → M个token向量

相似度 = MaxSim：每个 query token 取与所有 doc token 的最大相似度之和
比 Bi-Encoder 精度高，比 Cross-Encoder 快
```

### 查询和文档用不同 Prompt

```
一些模型（如 E5）需要给 query 和 document 加不同前缀：
query: "query: 什么是 RAG？"
doc: "passage: RAG 是检索增强生成..."

这帮助模型区分"搜索意图"和"文档内容"
```

## 面试常见问题

**Q1：余弦相似度和欧氏距离的区别？什么时候用哪个？**
A：余弦相似度只看方向不看长度，适合文本相似度；欧氏距离考虑绝对位置。如果向量已归一化，两者等价。默认用余弦相似度。

**Q2：HNSW 索引的原理？**
A：构建多层图，每层是近邻图。查询从最高层（最稀疏）开始贪心搜索，逐层向下到最底层（所有向量）。类似跳表，查询时间 O(log n)。

**Q3：嵌入维度越高越好吗？**
A：不一定。维度越高表达力越强，但存储/计算成本增加，且可能出现维度灾难。实际中 768-1536 维通常足够。可以用 Matryoshka 嵌入做维度-精度权衡。

---

## 一句话总结

向量检索 = 嵌入模型（文本→向量）+ 相似度度量（余弦/欧氏/点积）+ 索引结构（Flat/IVF/HNSW），三者的选择决定了检索的精度、速度和成本。
