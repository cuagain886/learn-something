# 06 · 内存管理与垃圾回收 ⭐⭐⭐

> CPython 的内存管理是**引用计数为主、分代垃圾回收为辅**。
> 引用计数实时回收大部分对象，分代 GC 负责处理循环引用。

---

## 1. 引用计数（Reference Counting）

每个 Python 对象都有一个引用计数字段 `ob_refcnt`：

```python
import sys

a = [1, 2, 3]
print(sys.getrefcount(a))  # N（getrefcount 本身会增加 1 次引用）

b = a                       # refcount +1
c = a                       # refcount +1
del b                       # refcount -1
c = None                    # refcount -1
# 当 refcount 降为 0 -> 立即释放内存
```

### 引用计数增加的时机
- 赋值：`b = a`
- 作为参数传入函数
- 加入容器：`lst.append(a)`
- 函数调用 `sys.getrefcount(a)` 本身

### 引用计数减少的时机
- `del` 语句
- 名字重新绑定
- 容器删除元素
- 函数返回（局部变量销毁）

### 引用计数的优缺点

| 优点 | 缺点 |
|------|------|
| 实时回收，无停顿 | 无法处理循环引用 |
| 实现简单 | 每次赋值都要更新计数（性能开销） |
| 回收时机确定 | 多线程下需要 GIL 保护 |

## 2. 循环引用与分代 GC

### 循环引用问题

```python
a = []
b = []
a.append(b)   # a -> b
b.append(a)   # b -> a  循环引用！

del a
del b
# a 和 b 的引用计数都是 1（互相引用），永远不会降到 0
# 引用计数无法回收！需要 GC 介入
```

### 分代垃圾回收

CPython 的 GC 使用**分代收集**（generational collection）算法：

```
┌────────────┐     ┌────────────┐     ┌────────────┐
│  第 0 代    │ ──→ │  第 1 代    │ ──→ │  第 2 代    │
│  (新对象)   │     │  (存活较久) │     │  (长期存活) │
│  频繁扫描   │     │  较少扫描   │     │  很少扫描   │
└────────────┘     └────────────┘     └────────────┘
```

- 新创建的对象进入第 0 代
- 第 0 代 GC 后存活的对象晋升到第 1 代
- 第 1 代 GC 后存活的对象晋升到第 2 代
- 每一代有独立的阈值，触发频率递减

```python
import gc

# 查看各代阈值
print(gc.get_threshold())  # (700, 10, 10)
# 含义：第 0 代分配 700 次后触发扫描
#       第 0 代扫描 10 次后触发第 1 代扫描
#       第 1 代扫描 10 次后触发第 2 代扫描

# 手动触发 GC
gc.collect()

# 查看 GC 统计
print(gc.get_stats())
```

### GC 的检测算法

```
1. 对每个容器对象，设 gc_refs = ob_refcnt
2. 遍历所有容器对象，对于每个引用 A -> B，将 B 的 gc_refs -= 1
3. gc_refs > 0 的对象从外部可达（根对象）
4. 从根对象出发，标记所有可达对象
5. 未标记的对象是循环垃圾，可以回收
```

## 3. 内存池（Memory Pool）

CPython 有三级内存管理：

```
┌──────────────────────────────────────┐
│ 第 3 层：Python 对象分配器            │  Python 对象专用
│ (pymalloc)                           │
├──────────────────────────────────────┤
│ 第 2 层：Python 内存分配器            │  Python 内部使用
│ (PyMem_Malloc)                       │
├──────────────────────────────────────┤
│ 第 1 层：C 标准库                     │  系统 malloc/free
│ (malloc/free)                        │
└──────────────────────────────────────┘
```

### pymalloc 小对象池

对于 ≤ 512 字节的小对象，CPython 使用 pymalloc 分配器：

- **Arena**（256KB）→ **Pool**（4KB）→ **Block**（8 的倍数，8~512 字节）
- 小对象从 pool 中分配，不直接调用系统 malloc
- ⚠️ 释放的小对象内存归还给 pool，不归还给操作系统（除非整个 arena 为空）

```python
# 这就是为什么 Python 进程的内存占用"只增不减"的原因
import os
print(f"RSS: {os.getpid()}")  # 进程内存

# 大量小对象创建-销毁后，进程内存不会下降
lst = [dict() for _ in range(1_000_000)]
del lst
# 内存仍然较高——小对象池保持在 Python 进程内部
```

## 4. 弱引用（weakref）

弱引用不增加引用计数，常用于缓存：

```python
import weakref

class Expensive:
    pass

obj = Expensive()
weak = weakref.ref(obj)

print(weak())     # <Expensive object>
del obj
print(weak())     # None（对象已被回收）

# WeakValueDictionary：值是弱引用的字典
cache = weakref.WeakValueDictionary()
```

## 5. 与 Go GC 的对比

| 特性 | Python (CPython) | Go |
|------|-----------------|-----|
| 主要机制 | 引用计数 + 分代 GC | 三色标记 + 写屏障 |
| 暂停时间 | 引用计数无暂停；GC 有短暂 STW | < 1ms STW |
| 循环引用 | 分代 GC 处理 | 标记-清除天然处理 |
| 回收时机 | 引用计数：立即；GC：周期性 | GC 触发时 |
| 内存归还 | 小对象不归还 OS | 定期归还 OS |
| 调优 | `gc.set_threshold()` | `GOGC` |

## 高频面试题

**Q1：Python 的垃圾回收机制是什么？**
A：以引用计数为主（对象引用数为 0 立即回收），以分代垃圾回收为辅（处理循环引用，分 0/1/2 三代，频率递减）。

**Q2：什么情况下引用计数失效？**
A：循环引用。两个或多个对象互相引用，引用计数永远不为 0，只能靠分代 GC 的标记-清除来回收。

**Q3：为什么 Python 进程的内存占用往往"只增不减"？**
A：因为 pymalloc 的小对象池。释放的小对象内存归还给内存池而非操作系统，除非整个 arena 为空。

**Q4：`gc.collect()` 什么时候需要手动调用？**
A：通常不需要。但在创建大量临时对象后、或明确知道存在循环引用需要立即回收时可以手动调用。

**Q5：`__del__` 析构方法可靠吗？**
A：不可靠。循环引用的对象如果定义了 `__del__`，Python 3.3 之前无法回收（放入 `gc.garbage`），3.4+ 可以回收但调用顺序不确定。资源清理应该用 `with` 语句（上下文管理器）。

---

## 一句话总结

CPython 用引用计数实时回收大部分对象，用分代 GC（三代，频率递减）处理循环引用；小对象通过 pymalloc 内存池管理，释放后通常不归还操作系统。
