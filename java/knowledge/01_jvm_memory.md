# 01 · JVM 内存结构（运行时数据区）⭐⭐⭐

> "new 一个对象，内存里发生了什么？"——几乎是 Java 面试的开场必问。核心一句话：
> **对象基本都在堆上分配，引用变量和方法调用信息在栈上，类的元数据在元空间。**

---

## 1. 运行时数据区全景

JVM 把它管理的内存划分为若干区域，按"是否线程共享"分两类：

```
┌───────────────────── 线程共享（所有线程一份）─────────────────────┐
│                                                                  │
│   堆 Heap（对象实例、数组）          方法区/元空间 Metaspace       │
│   ├── 新生代 Young                   （类元数据、运行时常量池、     │
│   │   ├── Eden                        静态变量、字符串常量池*）     │
│   │   ├── Survivor 0                                              │
│   │   └── Survivor 1                                              │
│   └── 老年代 Old                                                  │
└──────────────────────────────────────────────────────────────────┘
┌───────────────── 线程私有（每个线程各一份）──────────────────────┐
│   虚拟机栈 JVM Stack    本地方法栈 Native Stack    程序计数器 PC   │
│   （栈帧：局部变量表、                              （当前字节码    │
│     操作数栈、动态链接、                              行号指示器）  │
│     返回地址）                                                    │
└──────────────────────────────────────────────────────────────────┘
* 字符串常量池在 Java 7 起已从永久代移到【堆】中（见文档 10）。
```

---

## 2. 各区域详解

### 2.1 堆 Heap —— 对象的家（GC 主战场）

- **存什么**：几乎所有**对象实例**和**数组**。是 GC 最主要管理的区域。
- **线程共享**，启动时创建，是最大的一块内存。
- **分代**（为配合 GC，见文档 03）：
  - **新生代 Young**：新对象先在这里。又分 Eden + 两个 Survivor（S0/S1，默认比例 8:1:1）。
  - **老年代 Old**：长寿对象（熬过多次 GC）或大对象晋升到这里。
- 参数：`-Xms` 初始堆、`-Xmx` 最大堆（生产常设为相等避免动态扩容）、`-Xmn` 新生代大小。
- 抛 **`OutOfMemoryError: Java heap space`**：对象太多/内存泄漏，堆放不下。

### 2.2 虚拟机栈 JVM Stack —— 方法调用的轨迹

- **线程私有**，生命周期与线程相同。
- 每调用一个方法，就压入一个**栈帧（Stack Frame）**；方法返回，栈帧弹出。
- 栈帧里装：
  - **局部变量表**：方法参数 + 局部变量（基本类型的值、对象的**引用**）。
  - **操作数栈**：字节码运算的工作区（如 `a + b` 在这里完成）。
  - **动态链接**：指向运行时常量池中该方法的引用。
  - **返回地址**：方法结束后回到哪里。
- 参数 `-Xss` 设栈大小（如 `-Xss512k`）。
- 两种错误：
  - **`StackOverflowError`**：栈太深（递归没出口）—— 栈帧压太多。
  - **`OutOfMemoryError`**：无法再申请栈空间（线程开太多）。

### 2.3 本地方法栈 Native Stack

- 与虚拟机栈类似，但服务于 **native 方法**（用 C/C++ 写的、由 JNI 调用的方法）。
- HotSpot 把它和虚拟机栈合二为一。

### 2.4 程序计数器 PC Register

- **线程私有**，是当前线程执行字节码的**行号指示器**。
- 线程切换后能恢复到正确的执行位置。
- 唯一**不会抛 OOM** 的区域。

### 2.5 方法区 / 元空间 Metaspace —— 类的"户口本"

- **线程共享**，存**类的元数据**（类结构、方法字节码、字段信息）、**运行时常量池**、**静态变量**。
- ⭐ **重大版本变化**：
  - **Java 7 及之前**：叫**永久代（PermGen）**，是堆的一部分，大小固定，易 `OutOfMemoryError: PermGen space`。
  - **Java 8 起**：永久代被**元空间（Metaspace）**取代，**移到本地内存（堆外）**，默认大小受物理内存限制（可用 `-XX:MaxMetaspaceSize` 限制）。
  - 同时**静态变量和字符串常量池移到了堆中**。
- 这是面试高频考点：**"Java 8 内存结构有什么变化？"答：永久代→元空间，移出堆进本地内存。**

## 3. 对象创建的完整过程（"new 发生了什么"）

```java
User u = new User("Alice");
```

1. **类加载检查**：检查 `User` 类是否已加载/链接/初始化，没有则先加载（见文档 02）。
2. **分配内存**：在**堆**上划一块内存。两种方式：
   - **指针碰撞**（内存规整时，如带压缩的 GC）：移动分界指针。
   - **空闲列表**（内存零散时）：从空闲块里找。
   - 并发安全：用 **CAS** 重试，或给每个线程预分配一小块 **TLAB**（Thread Local Allocation Buffer），各线程在自己的 TLAB 里分配，免锁。
3. **零值初始化**：所有字段设默认值（0/null/false）。
4. **设置对象头**：填入 Mark Word（哈希、GC 年龄、锁信息，见文档 05）和类型指针。
5. **执行构造器 `<init>`**：按代码给字段赋真正的值。
6. 把堆中对象的**地址**赋给栈上的引用变量 `u`。

> **对象在堆还是栈？** 默认在堆。但 JIT 做**逃逸分析**后，若发现对象不会逃出方法作用域，可能做**栈上分配 / 标量替换**，对象就不进堆了（这是优化，不能依赖）。

## 4. 对象的内存布局

一个对象在堆中分三部分：

```
┌──────────────────────────────────────────┐
│ 对象头 Object Header                       │
│   ├── Mark Word（8B）：哈希码/GC年龄/锁状态  │  ← 锁升级就改这里（文档 05）
│   └── 类型指针 Klass Pointer（开启压缩指针 4B）│  ← 指向元空间的类元数据
│ (数组还多一个 length 字段)                  │
├──────────────────────────────────────────┤
│ 实例数据 Instance Data：各字段的值          │
├──────────────────────────────────────────┤
│ 对齐填充 Padding：补齐到 8 字节的整数倍      │
└──────────────────────────────────────────┘
```

> 可用 OpenJDK 的 **JOL** 工具 `ClassLayout.parseInstance(obj).toPrintable()` 实测布局。
> Java 25 延续 Project Lilliput 方向，在持续压缩对象头，未来 Mark Word 会更小。

## 5. 高频面试题 + 标准答案

**Q1：JVM 运行时数据区有哪几块？哪些线程共享？** ⭐
> 堆、方法区（元空间）线程共享；虚拟机栈、本地方法栈、程序计数器线程私有。堆放对象，栈放栈帧（局部变量+方法调用），元空间放类元数据。

**Q2：Java 8 的内存结构相比之前有什么变化？** ⭐⭐
> 永久代（PermGen，在堆内、大小固定）被**元空间（Metaspace，在本地内存、受物理内存限制）**取代。同时字符串常量池和静态变量从永久代移到了堆中。好处：避免了 PermGen 易溢出且难调优的问题。

**Q3：堆和栈的区别？**
> 堆：线程共享、存对象实例、GC 管理、大、慢一点。栈：线程私有、存栈帧（局部变量+引用）、随方法进出自动分配回收、小、快。对象在堆，引用在栈。

**Q4：StackOverflowError 和 OutOfMemoryError 区别？**
> SOF：栈深度超限（通常递归无出口），属虚拟机栈。OOM：内存不足无法分配，常见于堆（对象太多/泄漏）或元空间（动态生成大量类）。

**Q5：一个对象从创建到回收经历了什么？**
> 类加载检查→堆上分配内存（指针碰撞/空闲列表 + TLAB/CAS 保证并发）→零值初始化→设对象头→执行构造器。之后在新生代经历 Minor GC，熬过多次后晋升老年代，最终不可达时被回收（文档 03）。

**Q6：对象一定分配在堆上吗？**
> 不一定。JIT 逃逸分析发现对象未逃逸时，可做栈上分配或标量替换，对象不进堆，方法结束随栈帧销毁，减轻 GC 压力。但这是优化，开发不能依赖。

---

## 一句话总结

> **堆放对象、栈放调用、元空间放类信息**；Java 8 把永久代换成了移到堆外的元空间；
> new 对象 = 类加载检查 → 堆上分配（TLAB/CAS）→ 零值 → 对象头 → 构造器。
> 记牢"对象头里的 Mark Word"（连着锁升级，文档 05）和"分代结构"（连着 GC，文档 03）。
