## 1. 地图不是目录复述

学习顺序由依赖关系决定：不了解类型和调用语义，就无法准确读字节码；不了解类加载和对象模型，就会把 JMM 说成“线程从主内存复制变量”；不了解超时的结果未知，就会在 Agent 工具调用中把重试变成重复副作用。

```text
语言设计 ──► 类型/OOP/泛型/异常/集合
   │                    │
   └────► javac ─► Class 文件 ─► 类加载 ─► 运行时区 ─► 对象/分配
                                      │                    │
                                      └────────► GC ◄──────┘
                                                   │
                                  解释器/JIT ◄─────┘
                                                   │
                       JMM ─► 锁/AQS ─► 线程池/虚拟线程
                        │                           │
                        └────► NIO/HTTP/Spring/DB/MQ/分布式
                                                    │
                  LLM/RAG/Tool ─► Agent 状态机 ─► 超时/取消/幂等/Sandbox
                                                    │
                                    可观测性与四类故障排查
```

## 3. 第一轮核心闭环

第一轮不是十篇互不相干的文章，而是同一段程序的生命周期：

```text
01 选择“字节码 + VM”的平台契约
 ↓
02 定义值、类型、控制流和 String 的语言语义
 ↓
04 javac 建 AST、解析符号、归因、解糖并生成
 ↓
05 Class 文件携带常量池、方法 Code、帧和属性
 ↓
06 loader 定义类型；验证、准备、解析、初始化
 ↓
07 线程用栈帧执行，元数据/堆/直接内存各有归属
 ↓
08 HotSpot 为实例布置 header、字段、对齐和引用
 ↓
15 多线程观察受 JMM 的 happens-before 约束
```

每章都至少反向链接一层。例如对象布局只说明 HotSpot 的物理实现，不能改写 JLS 中“引用值”的抽象语义；JMM 定义允许观察，具体 fence 序列由 HotSpot 后端和 CPU 决定。

## 4. 四种证据，不互相冒充

| 证据 | 能证明 | 不能单独证明 |
|---|---|---|
| JLS/JVMS 条款 | 所有合规实现必须满足的语义 | HotSpot 对象头位布局、某 CPU 指令 |
| OpenJDK 源码/JEP | 指定版本实现与设计背景 | 其他 JVM 或未来版本必然相同 |
| 工具输出 | 该进程、参数、负载下的观测 | 未观测到的行为“不可能” |
| 压测/基准 | 固定实验世界中的分布与差异 | 线上外推、因果关系或语义正确性 |

结论模板：

> 在 **JDK/VM/OS/参数** 下，根据 **规范或源码路径**，预测 **可观察结果**；使用 **命令和对照组** 得到 **输出**；结果只支持 **边界内主张**，替代解释是 **X**。

## 5. 能力矩阵与毕业标准

| 能力 | 最低证据 | 达标标准 |
|---|---|---|
| 字节码阅读 | `javap -c -v -p` | 能手算简单方法的栈变化，解释 CP 引用与异常表 |
| JVM 内存 | JOL、NMT、heap dump、GC log | 不混淆 heap、metaspace、native、RSS、container |
| 并发正确性 | JLS 17.4 推导 + JCStress | 先列允许结果，再写测试，不用 sleep 证明正确 |
| 后端容量 | 池/队列/延迟指标 | 能说明瓶颈资源、排队点、超时与拒绝策略 |
| Agent 可靠性 | 状态机与故障注入 | 重放不重复副作用，取消能回收子任务，结果未知可对账 |
| 诊断 | 时间线与多源证据 | 从现象定位资源，再落到代码路径并做同负载验收 |

## 6. 章节使用节奏

每一章按“预测—执行—解释—扰动—复盘”学习：

1. 阅读前先写预测，尤其是字节码、初始化顺序和并发允许结果。
2. 运行基线并保留 JDK、参数、命令、原始输出。
3. 只解释工具真正观测到的量。
4. 改一个变量做对照：JDK、压缩指针、`volatile`、堆上限或类加载器。
5. 把结论应用到一个后端/Agent 失败场景。

跳过第 4 步，通常只是在记结果；跳过第 5 步，通常还不能用于工程。
