1. 为什么 JS 是异步的？—— 单线程 + 事件循环

JS 引擎是单线程的（一份代码、一个调用栈），但它能通过事件循环（Event Loop）高效处理并发 I/O：

  • 同步代码 → 直接入调用栈执行（阻塞）
  • 异步代码 → 交给 Web API（浏览器）→ 回调入任务队列 → 调用栈空后执行

这解释了为什么 setTimeout(fn, 0) 不会立即执行 —— 它必须等当前调用栈清空。

💡 关键理解：JS 不会"暂停"等异步结果，而是"注册一个回调，继续执行下面的代码，等结果回来了再调用回调"。

2. Promise —— 异步操作的承诺

Promise 有三种状态：pending（进行中）→ fulfilled（成功）/ rejected（失败）。状态一旦改变就不能再变。

方法作用
.then(fn)成功时执行（可以链式调用）
.catch(fn)失败时执行
.finally(fn)无论成功失败都执行
Promise.all([...])全部成功 → 成功；任何一个失败 → 失败
Promise.allSettled([...])等全部完成（不管成败），返回每个的结果
Promise.race([...])返回第一个完成的（不管成败）
Promise.any([...])返回第一个成功的；全失败才 reject

3. async / await —— 最优雅的异步写法

async 函数总是返回 Promise；await 只能在 async 函数内部使用，它会"暂停"函数执行直到 Promise 完成。

💡 推荐：现代 JS 开发中，async/await 是异步代码的首选风格。只有在需要精细控制并发时才回到 Promise 链式调用。
⚠️ await 陷阱：多个独立的 await 顺序执行是浪费！如果两个异步操作互不依赖，用 Promise.all 并行执行。
