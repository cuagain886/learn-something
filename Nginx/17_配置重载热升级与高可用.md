# 配置重载、热升级与高可用

## 1. reload 事务边界

master 收到 HUP 后解析完整新配置并打开资源。

任何关键步骤失败则保留旧 cycle，不启动半配置 worker。

成功才 fork 新 worker 并通知旧 worker 优雅退出。

## 2. 旧 worker 排空

旧 worker 关闭监听事件，不再 accept 新连接，但继续：

- 当前请求。
- keepalive/HTTP2/WebSocket 长连接。
- upstream 交互。

若不限制 shutdown timeout，长连接可让旧 worker 存活数小时；限制则到点强制关闭。

## 3. reload 内存峰值

新旧 workers 共存，配置、连接 pool、TLS context 和部分进程内 cache 双份。

共享 zone 可复用，但普通 worker RSS 不共享所有修改页。

内存紧张时 reload 可能触发 OOM，容量要预留重载峰值。

## 4. 资源变化

- listen 不变：复用 fd。
- 新 listen：master bind/open。
- 删除 listen：旧 worker 仍持有直到退出。
- 日志变化：新 cycle 打开新文件。
- shared zone：由模块判断兼容/复用。
- 证书：新 worker 加载新 context。

## 5. 日志轮转

外部 rename 日志后发送 USR1，master/worker reopen 新路径。

若只 rename 不 reopen，进程继续写旧 inode，磁盘空间不会释放。

copytruncate 有数据竞争和丢行风险，优先 rename+reopen。

## 6. 二进制热升级

USR2 等流程可启动新 binary master，与旧 master/worker 共存，再逐步关闭旧 workers并保留回滚可能。

这是高级运维：PID 文件、模块 ABI、共享内存、监听 fd 和回退信号都需按官方流程演练。

容器环境通常用滚动替换实例更简单。

## 7. 配置发布流水线

```text
生成配置到临时目录
-> 静态 lint/安全检查
-> nginx -t -c candidate
-> canary 实例 reload
-> 功能与故障探针
-> 小流量观察
-> 全量发布
-> 验证新 worker/旧 worker排空
-> 保留上一版本回滚
```

避免远程直接 sed 生产 nginx.conf。

## 8. 高可用层次

- 单机多 worker 只隔离 worker crash。
- 多 Nginx 实例隔离主机故障。
- 前置 L4/VIP/DNS负责实例发现与切换。
- 跨机房需健康、路由、证书、配置和状态同步。

proxy cache、limit zone 等本地/单实例状态不会自动跨节点复制。

## 9. readiness

readiness 不应只返回 Nginx 本地 200。

也不能同步检查所有后端导致依赖抖动把全部网关摘除。

分层：进程/配置就绪、关键资源就绪、后端状态作为路由降级指标。

## 10. 回滚

配置回滚不一定恢复运行状态：

- cache 已污染。
- DNS 已变化。
- upstream 发布已前进。
- TLS ticket/证书已轮换。
- 旧 worker 已退出。

runbook 要列出配置和外部状态。

## 11. 面试追问

问：reload 是否绝对零中断？

答：监听和已有连接可平滑交接，但 worker crash、资源不足、shutdown timeout、长连接、客户端重试和错误配置仍可能造成中断或语义变化。
