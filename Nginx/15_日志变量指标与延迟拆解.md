# 日志、变量、指标与延迟拆解

## 1. 先定义时间

```text
$request_time: Nginx 从读到请求首字节到日志阶段的总时间
$upstream_connect_time: 建连，HTTPS 后端通常含握手
$upstream_header_time: 建连后到完整响应 header
$upstream_response_time: 与某次 upstream 交互总时间
```

多次 upstream 尝试产生逗号/冒号分隔序列，必须与 `$upstream_addr` 对齐解析。

## 2. 延迟归因

- request_time 高，upstream_response_time 低：慢客户端上传/下载、Nginx 排队/filter/log 等。
- connect_time 高：网络、SYN、TLS、端口/队列。
- header_time 高：应用排队/处理到首字节慢。
- response-header 差大：响应体慢或客户端/缓冲影响。

它们不是严格可直接相减的所有场景，重试和缓冲需结合时间线。

## 3. 结构化日志

推荐 JSON 但必须正确 escape：

```nginx
log_format json escape=json '{"request_id":"$request_id","status":$status,...}';
```

字段包括：时间、request/connection ID、remote/real IP、host、method、uri、status、bytes、request time、upstream 序列、cache status、TLS/protocol。

不要记录 Authorization、Cookie、完整敏感 query/body。

## 4. 最终状态与 upstream 状态

Nginx 最终 200 可能来自 stale cache，而 upstream 是 503。

最终 404 可能是 error_page 内部处理。

同时记录 `$status` 与 `$upstream_status`、cache status 才能看见被隐藏的故障。

## 5. 499

常见 499 表示客户端在 Nginx 完成响应前关闭连接，是 Nginx 非标准状态。

根因可能是：

- 用户取消。
- 前置 LB timeout 比 Nginx 短。
- upstream 太慢导致客户端超时。
- 网络断开。

不能简单归责客户端。

## 6. error_log 级别

debug 日志信息丰富但开销和敏感数据风险高。

可按特定客户端 `debug_connection` 缩小范围。

生产临时开启前评估磁盘、CPU和日志权限。

## 7. stub_status/API

基础指标：active、accepts、handled、requests、reading/writing/waiting。

`handled < accepts` 可提示连接资源不足等。

这些不能替代每 upstream、每 location 的应用指标。

## 8. 指标体系

- 流量：RPS、连接建立、协议。
- 结果：2xx/4xx/5xx/499。
- 延迟：request/connect/header/response histograms。
- 饱和：active/waiting、worker CPU、fd、内存。
- upstream：peer 错误、重试、连接复用。
- cache：HIT/MISS/STALE、磁盘。
- TLS：handshake error、reuse、证书有效期。

平均值会隐藏尾延迟，使用 histogram/P99。

## 9. request ID 与 trace

若接受上游 request ID，必须验证长度/字符并避免冲突；可由边缘生成并向后端传递。

Nginx access log、应用日志和下游调用使用统一 ID。

采样 trace 不能替代完整指标。

## 10. 日志阻塞

日志写入仍有 I/O 成本。

buffered logging、syslog 和异步采集各有丢失/背压边界。

磁盘满会影响请求和 cache temp，应隔离容量并监控 inode。

## 11. reload 观测

记录 master/worker PID、配置版本和启动时间。

reload 后观察：新 worker 是否健康、旧 worker 排空、错误率、连接和 RSS 是否双份峰值。

## 12. 面试追问

问：upstream_response_time 0.001 而 request_time 30s 说明后端快吗？

答：该 upstream 尝试本身快，但请求总时间可能耗在客户端慢传/慢读、其他尝试、内部处理或日志；需结合 buffering、bytes 和多值序列。
