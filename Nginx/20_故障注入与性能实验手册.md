# 故障注入与性能实验手册

## 1. 实验纪律

隔离环境固定 Nginx/内核/OpenSSL版本、配置、CPU限额和 upstream。

每个实验先写假设、指标和通过条件。

## 2. 慢请求头

每几秒发送一个 header 字节，验证 client_header_timeout、连接/fd和内存。

通过条件：超时正确、健康请求 P99 不显著恶化、日志可归因。

## 3. 慢上传

上传大 body，分别开启/关闭 request buffering。

观察 upstream 连接持续时间、temp file、磁盘、重试可能性。

## 4. upstream 三阶段慢

分别制造：

- connect 不完成/拒绝。
- 接受后不读请求。
- 读完后迟迟不发 header。
- header 后慢速 body。

验证 connect/send/read timeout 的边界和 502/504日志阶段。

## 5. 非幂等重试

后端写 DB 后主动 reset，不返回响应。

检查 Nginx 是否重试、数据库是否重复、idempotency key 是否拦截。

## 6. 慢客户端下载

buffering 开/关对比 upstream 释放、Nginx RSS、temp disk 和 fd。

## 7. cache stampede

热点 key 过期同时发 1000 请求。

比较 cache lock、stale updating、background update 的回源数和尾延迟。

## 8. reload

保持 WebSocket、HTTP/2 和长下载，连续 reload。

观察旧 worker 数、RSS峰值、连接是否断开、shutdown timeout。

## 9. worker crash

kill 单 worker，验证 master 拉起时间和该 worker连接中断。

客户端 POST 不确定结果必须对账。

## 10. fd/connection 耗尽

降低 nofile/worker_connections 并压满。

观察 accepts/handled、error log、前置 LB重试和恢复。

## 11. disk full

限制 temp/cache/log 文件系统容量。

验证大上传、proxy buffering、cache write、access log 的失败隔离。

## 12. TLS

关闭 session reuse、制造握手洪水，观察 worker CPU和普通请求延迟。

测试错误链、过期证书、无 SNI、SNI/Host不一致和证书 reload。

## 13. HTTP/2/3

单连接大量 streams、大/小响应混合、丢包和客户端不读。

观察 per-stream内存、flow control和协议回退。
