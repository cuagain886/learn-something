# Nginx 深度学习计划

## 第一阶段：建立对象模型

阅读 01—04。

学习目标：

- 区分 master、worker、cache manager、cache loader。
- 理解 `ngx_cycle_t`、`ngx_connection_t`、`ngx_event_t`、`ngx_http_request_t` 的生命周期。
- 解释 epoll readiness 与“异步执行完成”的区别。
- 画出一个 keepalive TCP 连接上多个 HTTP/1.1 请求的对象关系。
- 解释 request pool 为什么能批量释放，又为什么不能保存跨请求指针。

实验：

1. 启动两个 worker，观察 PID 与父子关系。
2. `nginx -s reload`，记录旧 worker 和新 worker 共存时间。
3. 用 `strace` 观察 epoll_wait、accept4、recv、sendfile。
4. 让一个客户端慢速发送 header，观察连接和 request timeout。
5. 使用 debug log 跟踪同一 connection/request 编号。

验收问题：

- 为什么 Nginx 少量 worker 可以管理大量连接？
- 为什么模块中调用阻塞 DNS/HTTP 库会拖慢整个 worker？
- reload 后旧配置为什么仍对旧连接生效？

## 第二阶段：请求路由和阶段引擎

阅读 05—06。

学习目标：

- 精确复述 listen address/port、default server、SNI、Host 的选择关系。
- 掌握 prefix、`^~`、regex、named location 和内部跳转。
- 区分 URI normalization、rewrite 和文件路径拼接。
- 理解 post-read、server-rewrite、find-config、rewrite、access、content、log 等阶段。
- 解释 `if` 为什么不是通用编程语言。

实验：

1. 设计包含 exact、prefix、`^~`、nested regex 的 location 集合并逐个 curl。
2. 用 `$uri`、`$request_uri`、`$document_uri` 对比编码与 rewrite。
3. 制造 rewrite loop，观察内部重定向上限。
4. 配置多个 access 模块，验证 `satisfy any/all`。
5. 对 root 与 alias 做带/不带尾斜杠实验。

验收问题：

- 为什么“正则写在前面所以先匹配”是错误的？
- `proxy_pass` 带 URI 与不带 URI 时，转发路径为何不同？
- rewrite 后为何可能重新执行 location 查找？

## 第三阶段：upstream、缓冲与缓存

阅读 07—10。

学习目标：

- 追踪 `ngx_http_upstream_t` 从创建到 finalize。
- 区分 connect timeout、send timeout、read timeout。
- 理解 passive failure、tries、backup、max_fails/fail_timeout。
- 解释请求缓冲与响应缓冲分别保护哪一端。
- 说明 cache metadata shared zone 与 cache body 磁盘文件的区别。
- 设计防 cache stampede 的锁、stale 和 background update 策略。

实验：

1. upstream 分别延迟 accept、header 和 body，映射各超时。
2. POST body 大于内存缓冲，观察临时文件。
3. 客户端以 1KB/s 读取大响应，对比 buffering on/off。
4. 连续 kill upstream，观察重试、状态码和日志中的多地址时间数组。
5. 并发请求同一过期 cache key，观察回源数量。

验收问题：

- 504 是否等于连接不上 upstream？
- 为什么关闭 buffering 会让慢客户端长期占用 upstream 连接？
- 为什么 cache key 漏掉 Authorization/Cookie 会造成越权？

## 第四阶段：TLS、协议与内核

阅读 11—18。

学习目标：

- 画出 TCP、TLS、HTTP 请求三个阶段的时间线。
- 解释 SNI 在 HTTP Host 之前，证书如何被选择。
- 区分 HTTP/2 stream 并发与后端 HTTP/1.1 连接。
- 理解 QUIC 在 UDP 上如何避免跨 stream 传输层队头阻塞。
- 计算 fd、连接、buffer、TLS、upstream 的容量。
- 区分 listen backlog、SYN backlog、accept queue 和应用连接上限。

实验：

1. `openssl s_client` 验证 SNI、ALPN、session reuse。
2. HTTP/2 单连接并发多个大/小请求，观察流量竞争。
3. 开关 keepalive、session cache，比较握手 CPU。
4. 压满 worker_connections，观察错误日志与 accept 行为。
5. TCP Stream 代理中使用 ssl_preread 按 SNI 分流。

## 第五阶段：源码、事故与生产设计

阅读 19—22。

学习目标：

- 从 `nginx.c` 追到 `ngx_init_cycle()` 和 worker loop。
- 从 accept handler 追到 `ngx_http_init_connection()`。
- 从请求行解析追到 phase engine 和 upstream。
- 能根据日志区分客户端慢、Nginx 饱和、DNS、连接、首字节和响应体慢。
- 能写出 reload、rollback、证书轮换和故障切换 runbook。

毕业项目：

构建一个包含以下能力的反向代理：

```text
HTTP -> HTTPS redirect
TLS1.2/1.3 + HTTP/2
两个 upstream + keepalive
幂等请求有限重试
静态文件与 API 分离
公开 GET cache + stale
登录/API 禁止 cache
限速、限连接、真实 IP
结构化 access log
优雅 reload 和回滚
```

对项目执行：慢客户端、慢 upstream、连接拒绝、半关闭、缓存击穿、证书错误、reload、worker kill 和磁盘写满实验。

## 学习方法

每个指令都回答六个问题：

1. 属于 main/events/http/server/location/upstream 哪个上下文？
2. 配置值在哪个模块 conf 结构中？
3. 子级是覆盖、合并还是追加？
4. 请求生命周期哪个阶段读取它？
5. 它消耗连接、内存、fd、磁盘还是 CPU？
6. 失败时在哪个日志变量和错误阶段可见？
