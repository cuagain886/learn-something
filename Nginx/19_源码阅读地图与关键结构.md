# Nginx 源码阅读地图与关键结构

## 1. 固定版本与构建参数

先记录 `nginx -V`：版本、OpenSSL、configure arguments、动态模块。

源码函数与模块能力必须和生产 binary 对应。

## 2. 目录

```text
src/core    字符串、pool、array、hash、rbtree、cycle、log
src/event   事件核心、timer、posted、connect、accept
src/event/modules epoll/kqueue等
src/http    HTTP core、request、phase、upstream、filter
src/http/modules proxy/cache/rewrite/gzip/ssl等
src/http/v2 HTTP/2
src/event/quic QUIC（具体目录随版本）
src/stream  TCP/UDP stream
src/os/unix 进程、socket、sendfile等平台层
```

## 3. 四个主对象

### ngx_cycle_t

一代配置/运行资源：pool、conf_ctx、connections、listening、open_files、shared_memory、old_cycle。

### ngx_connection_t

fd、read/write event、pool、data、I/O函数指针、log。

### ngx_http_request_t

connection、main/parent、pool、headers、URI、conf arrays、phase_handler、upstream、output state、count。

### ngx_http_upstream_t

peer、请求 buffers、响应 buffers/pipe、headers_in、conf、state、callbacks。

## 4. 阅读顺序

1. `nginx.c:main` 到 `ngx_init_cycle`。
2. master/worker process cycle。
3. event module 初始化和 epoll loop。
4. accept 到 `ngx_http_init_connection`。
5. request line/header parser。
6. phase engine。
7. core location/content。
8. proxy module 创建 upstream。
9. upstream connect/send/read/retry/finalize。
10. header/body filter 和 request finalize。

## 5. handler 驱动阅读法

遇到函数设置：

```c
r->read_event_handler = ...;
r->write_event_handler = ...;
c->read->handler = ...;
```

立刻记录“下一次什么事件触发哪个函数”。

Nginx 源码大量逻辑不在当前调用栈继续，而在未来 event 回调。

## 6. pool 生命周期

标注每个分配来自 cycle、connection、request、temporary pool 或 shared slab。

回答谁销毁、异步回调是否还持有。

这是理解内存错误的关键。

## 7. 模块阅读模板

- module context 与 command table。
- create/merge conf。
- postconfiguration 注册哪个 phase/filter。
- 请求 handler 入口。
- 异步时如何保存状态和增加引用。
- finalize/cleanup。
- reload 时共享状态如何处理。

## 8. upstream 断点

```text
ngx_http_upstream_create
ngx_http_upstream_init
ngx_http_upstream_connect
ngx_http_upstream_send_request
ngx_http_upstream_process_header
ngx_http_upstream_process_upstream
ngx_http_upstream_next
ngx_http_upstream_finalize_request
```

每次记录 `r->count`、peer、read/write handler、timeout timer、state 数组。

## 9. 调试构建

使用 `--with-debug`，保留符号，降低优化用于 gdb。

生产复现注意 debug log 开销；隔离环境结合 gdb、rr、ASAN（若兼容构建）、Valgrind和 core dump。

## 10. 源码结论格式

记录：版本/commit、构建模块、入口、前置状态、修改对象、下一 handler、timer、返回码、cleanup、日志、可复现实验。

不要只摘函数名和注释。
