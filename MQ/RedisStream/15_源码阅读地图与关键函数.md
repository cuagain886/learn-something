# 源码阅读地图与关键函数

## 版本固定

先 checkout 与生产一致的 Redis tag，再阅读。函数名可能重构，下面是导航关键词而非稳定 API。不要引用 `unstable` 分支的结构解释旧集群。

## 文件地图

| 文件 | 关注点 |
|---|---|
| `src/t_stream.c` | Stream 类型、命令入口、迭代器、group/PEL、RDB 辅助 |
| `src/rax.c`, `rax.h` | 压缩 radix tree 插入、查找、迭代、删除 |
| `src/listpack.c`, `listpack.h` | 紧凑编码、遍历、替换和删除 |
| `src/server.c` | 命令执行、dirty、传播、ready keys |
| `src/networking.c` | 客户端响应与输出缓冲 |
| `src/aof.c`, `rdb.c` | 持久化写入、加载、rewrite |
| `src/replication.c` | 命令传播、offset、PSYNC/backlog |
| `src/cluster.c` | slot、重定向和 failover |

## 阅读 XADD

从命令表找到 `xadd` 的 handler（常见名称 `xaddCommand`），按以下问题单步：

1. 参数如何区分 NOMKSTREAM、MAXLEN/MINID、精确/近似、LIMIT？
2. key 不存在/类型错误如何处理？
3. 自动 ID 在哪里基于最后 ID 生成，回拨怎样处理？
4. 何时选择尾部 listpack，何时新建 rax 宏节点？
5. trim 如何按宏节点和删除条目计数？
6. dirty、key notification、阻塞唤醒、AOF/replica propagation 何时发生？

重点看传播的确定性：重放端不能再次依据自己的当前时间作不同决定。

## 阅读 XREAD/XREADGROUP

从 `xreadCommand` 附近区分普通读取和 group 分支：如何解析多 key/ID；如何定位大于 ID 的第一条；group 的 `>` 如何推进 last-delivered、创建 PEL；非 `>` 如何按 consumer PEL 读取；无数据时如何把 client 注册为 blocked；XADD 后 ready key 怎样唤醒。

把“注册阻塞”和“唤醒后重新检查条件”画成时序，确认 Redis 主线程没有睡眠等待。

## 阅读 PEL

搜索 `streamCG`、`streamConsumer`、`streamNACK` 等类型（名称以版本为准）。验证：组级与 consumer 级索引怎样引用同一个 pending 元数据；XACK 如何从两处删除；claim 如何检查 idle、更新 owner/time/count；删除 payload 时 PEL 是否同步更新以及版本策略。

关键不变量：任何所有权转移都要让两个索引一致；否则 XPENDING 按组和按 consumer 会矛盾。

## 调试实验

使用 debug build/gdb：

1. 在 XADD 命令入口断点，单步生成 ID和追加。
2. 写入直到宏节点分裂，观察 rax key 数与 XLEN 不相等。
3. XREADGROUP 一条，比较前后 group/consumer PEL。
4. XCLAIM 后验证 owner 变更而 payload 不变。
5. XDEL pending 消息，观察主体与 PEL 分离。
6. 触发 AOF rewrite 后重启，检查组状态。

## 阅读产出模板

每条源码结论记录：Redis tag/commit、入口函数、核心数据结构、前置条件、修改状态、复杂度、传播/持久化、阻塞唤醒、错误路径、对应实验。这样结论能随版本复核，而不是堆函数名。
