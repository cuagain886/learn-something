# 容量规划、监控与排障

## 先建流量模型

定义：峰值生产 `Rp` 条/s，消费 `Rc` 条/s，平均条目内存成本 `B`，保留 `T` 秒，安全系数 `S`。稳态主体容量近似：

```text
entries = Rp × T
stream_memory ≈ entries × B × S
backlog_growth = max(0, Rp - Rc) × incident_duration
```

`B` 不能只取 payload 字节；应以真实字段、ID、rax/listpack、key、allocator 通过 `MEMORY USAGE` 实测。还要加 group/consumer/PEL 元数据、AOF rewrite/RDB fork COW、复制缓冲、客户端输出缓冲和碎片。

例如 20k/s、实测 420B/条、保留 6h，主体约 169GiB，尚未含副本与峰值。这往往已经提示 Redis 内存日志不是经济选项。

## 四类积压必须分辨

| 现象 | lag | PEL | 解释 |
|---|---:|---:|---|
| 生产快于领取 | 上升 | 可能低 | worker 没拿到消息 |
| 领取快、处理慢 | 低 | 上升 | 消息卡在业务处理/ACK |
| 全部完成 | 低 | 低 | 仍需看错误与延迟 |
| 裁剪过快 | 可能异常/未知 | 有悬空项 | payload 可能已丢 |

只监控 XLEN 无法判断任何一个组的健康；只监控 lag 会漏掉 PEL 堵塞。

## 核心指标

- 输入：XADD rate、失败率、P50/P99、平均/最大消息字节。
- 消费：每组 delivery rate、completion/ACK rate、lag、PEL size、oldest idle、claim rate、DLQ rate。
- 内存：`used_memory`、RSS、fragmentation、key MEMORY USAGE、evicted_keys。
- 持久化：AOF size/rewrite、RDB/AOF last status、fork duration、COW bytes、fsync delay。
- 复制：role、connected replicas、replication lag/offset、full resync、failover 次数。
- 客户端：blocked clients、connected clients、输出缓冲、连接池等待、超时。
- 主线程：command latency、SLOWLOG、CPU、网络和大响应。

## 延迟拆分

```text
end_to_end = producer_to_xadd
           + wait_before_delivery
           + time_in_PEL_before_start
           + business_processing
           + ack_latency
```

在消息字段记录可信 producer timestamp，在消费者记录 receive/start/commit/ack 时间。时钟不同主机时需 NTP 并把结果视为近似。Stream ID 时间不能替代完整埋点。

## 常见排障树

### lag 上升、PEL 不高

查消费者实例数、阻塞连接是否断开、组是否读错 key、是否 NOGROUP、客户端是否一直用错误 ID、Cluster 路由和生产突增。

### PEL 上升、lag 很低

查数据库/HTTP P99、线程池饱和、ACK 连接池、异常是否吞掉、批次过大、消费者 GC。对 oldest idle 抽样 XPENDING，再核对业务幂等表。

### 内存不随 XDEL 下降

查逻辑删除与宏节点回收、allocator 碎片、RSS、fork COW；对比头部 XTRIM 与随机 XDEL。不要因 RSS 未降就立即执行危险重启。

### 延迟周期性尖刺

关联 RDB/AOF rewrite、fork、fsync、active defrag、大批 trim/claim、慢 Lua、全量复制和宿主机噪声。

## 限流与背压

Redis Stream 不会替业务自动限制生产者。设置：最大允许 lag/内存水位；达到软阈值降低非关键生产；硬阈值拒绝/降级并写可靠外部缓冲。绝不能依赖 `maxmemory` 淘汰队列 key：任何淘汰都可能造成不可恢复消息丢失。MQ 实例建议 `noeviction` 并做提前容量控制。

## SLO 示例

- 99.9% 事件 30 秒内完成，而非仅“被领取”。
- PEL oldest idle < 2×正常处理 P999。
- DLQ < 0.01%，且 15 分钟内有人接手。
- 生产峰值持续 30 分钟仍保留 2 小时恢复窗口。
- 单主故障 RTO < 60 秒；RPO 明确承认异步复制窗口并由 outbox 补发。
