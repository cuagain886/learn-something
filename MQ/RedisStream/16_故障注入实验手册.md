# 故障注入实验手册

## 实验纪律

仅在隔离环境执行。每次固定 Redis/客户端版本、配置和数据集；记录命令时间线、event_id、Stream ID、主从 offset、AOF/RDB 状态。先写假设和判定条件，再注入故障，避免只截图“看起来正常”。

## 实验一：业务成功、ACK 丢失

消费者提交数据库后，在 XACK 前 kill -9。重启/claim 后验证消息重复投递，数据库唯一键阻止第二次副作用，然后 ACK。验收：effectively-once，而不是“没有重复投递”。

## 实验二：错误顺序造成丢失

测试消费者先 XACK，再在 DB commit 前 kill。验证 PEL 已无记录且业务缺失。此实验用于代码审查教育，证明顺序为何不可反。

## 实验三：claim 双执行

让 C1 处理时暂停超过 min-idle，C2 XAUTOCLAIM 后开始处理，再恢复 C1。验证两者都可能运行，但状态机/幂等只产生一次结果。逐步提高 min-idle，观察误 claim 与故障恢复速度取舍。

## 实验四：裁剪 pending payload

领取但不 ACK，XTRIM/XDEL 越过该 ID，再读 pending 和 XPENDING。记录空 payload 与 PEL。测试当前版本引用策略命令。验收：恢复器能输出可审计 `payload_missing`，不会空指针或假 ACK。

## 实验五：主从切换丢失窗口

制造副本延迟，执行 XADD 后立即终止主并触发切换。分别测试无 WAIT、WAIT 1、不同持久化策略。不要预设一定能复现；用大量迭代统计并记录被晋升副本。验证 WAIT 降低概率而非提供共识承诺。

## 实验六：AOF/RDB 恢复

在不同 fsync 策略下写消息、读取进 PEL、ACK/claim，然后进程崩溃与机器级故障分别模拟。从文件恢复，比较 payload、last-delivered-id、PEL owner/count。再做 rewrite 期间高写入，观察 fork、COW 和 P99。

## 实验七：消费能力骤降

生产保持阶梯流量，逐步增加 DB 延迟或减少 worker。记录 lag、PEL、oldest idle 和内存斜率，找到最早能预警的指标。验证本地 worker 队列满后读取是否停止。

## 实验八：毒消息与重试风暴

注入不可解析、大 payload、永久业务错误和下游 429。验证单消息不会 crash loop；指数退避与 jitter；达到上限转 DLQ；系统性故障触发熔断而不是每条快速重试。

## 实验九：Cluster 迁槽

阻塞读取期间迁移 Stream slot，记录 MOVED/ASK、连接重建、重复/漏读和 PEL。验证客户端没有用 `$` 重置位置。测试主流与 DLQ 跨 slot 时原子脚本失败及补偿路径。
