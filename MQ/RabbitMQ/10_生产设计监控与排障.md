# 10｜生产设计、监控与排障：从 SLO 选择数据结构

## 1. 先定义 SLO

```text
峰值 messages/s 与 bytes/s
消息平均/p99 大小
Publisher 可接受 p99 与超时
允许重复还是允许漏处理
Ready/Unacked 最大积压和恢复时间
单节点/机架/地域故障目标
是否需要重放、保留期、严格顺序
```

没有这些信息不能给 Queue 类型、副本、Prefetch、TTL 或 Channel 数。

## 2. 拓扑设计

- 命令/任务按领域使用 Direct/Topic Exchange；
- 不同消费目的使用不同 Queue，避免一个 Queue 上混合独立订阅语义；
- 关键长期工作队列用 Quorum；临时可重建用 Classic；重放/长积压用 Stream；
- Queue/Binding 命名包含领域而非实例 ID；临时 Queue 使用服务端名；
- 可变 TTL/DLX/长度优先 Policy；
- 每条消息有 eventId、schemaVersion、occurredAt、traceId。

## 3. 容量与恢复

```text
backlogBytes = maxBacklogMessages × avgStoredBytes
replicatedBytes ≈ backlogBytes × replicaCount × overhead
catchupTime ≈ backlog / (ackRate - publishRate), ackRate > publishRate
```

还需测索引、Quorum log、DLX pending、恢复临时空间和磁盘安全余量。Queue 消息数不能替代字节容量。

## 4. 监控四层

### Publisher

Publish rate/bytes、Confirm Ack/Nack/timeout、Return、Pending 数/年龄、blocked/unblocked、Connection recovery。

### Queue

Ready/Unacked/total 与 bytes、Publish/Deliver/Ack/Redelivery rate、Consumer 数/利用率、Leader/成员、Queue state、消息年龄。

### Node

Memory/disk alarm、磁盘 free/time-to-full、IO latency、Erlang process/mailbox、CPU/scheduler、网络、Connection/Channel 数、file descriptors。

### 业务

eventId 去重、处理成功/失败/重试/DLQ、数据库 p99、状态版本冲突、端到端延迟和对账差异。

## 5. Ready 堆积故障树

1. Publish rate 是否突增；
2. Ack rate 是否下降；
3. Consumer 数是否为 0/减少；
4. Deliver rate 是否低：Queue/节点/网络问题；
5. Deliver 正常但 Ack 低：业务/DB 慢；
6. 是否集中少数 Queue/Leader 节点；
7. Redelivery 是否异常形成循环；
8. 是否被 Single Active Consumer/低 Prefetch 限制。

增加 Consumer 只在可并行且瓶颈不在共享下游时有效。

## 6. Unacked 堆积故障树

Unacked 高说明消息已到 Consumer：查处理线程池、数据库、死锁、Ack Channel、prefetch、GC 和 Consumer 是否吞下消息后停止确认。

止血可降低 prefetch、暂停上游、恢复下游；直接重启 Consumer 会让大量 Unacked 重投，可能制造重复风暴，先确保幂等和容量。

## 7. Confirm 变慢

检查是否单 Queue/类型：Quorum 复制慢、失去成员、Leader 节点磁盘慢；还是全节点资源告警/IO。再查消息大小、Fanout 目标、Nack/Return、Publisher Pending 与 Connection blocked。

增大 Confirm timeout 会隐藏尾延迟并增加 Pending，不是根治。

## 8. 安全变更

- 滚动升级前确认所有 Quorum Queue/Stream 有多数派且同步；
- 一次不要同时停止可能构成同一多数派的多个节点；
- Policy 变更先小范围验证，特别是 TTL/DLX/max-length；
- Queue 类型迁移用新 Queue 和对账，不原地重声明；
- 扩节点后检查 Queue members/Leader 分布，不假设自动均衡；
- 灾备用 Federation/Shovel/跨集群复制策略时明确异步 RPO，不把 WAN 节点直接拼成低延迟 Cluster。

## 9. 订单系统参考

```text
order.events topic exchange
payment.order.paid quorum queue, 3 members
Publisher: mandatory + async confirms + bounded pending + outbox
Consumer: manual ack + prefetch measured + inbox unique(eventId)
Retry: 5s/1m/10m, total 5 attempts, parking queue
Order: orderId routing/sharding + version conditional update
```

监控从 Return、Confirm、Ready/Unacked、Redelivery 一直延伸到 DB 幂等和订单对账。
