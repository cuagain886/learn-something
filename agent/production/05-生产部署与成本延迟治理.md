# 05 · 生产部署与成本延迟治理

> 目标：把 Agent **稳、省、可控**地推上线——渐进发布、可靠性、成本/延迟治理、扩展、回滚与治理。这是安全之外的生产工程关注点。

---

## 1. 渐进发布：别一步到位 ⭐

Agent 行为不确定、能采取真实动作，**绝不要一上来就全量、全自主、高风险地放出去**。业界标准是**分阶段渐进**：

```
1. 影子模式 / 试点：Agent 先在低风险场景、小流量、或"只建议不执行"模式跑
2. 人工监督：高风险动作全程 HITL（文档04），积累信任和数据
3. 逐步放权：用评估和线上数据证明可靠后，逐步扩大流量、降低人工介入、放开更多动作
4. 全量 + 自动：在有充分护栏、监控、回滚的前提下full自动
```

> 原则：**自主权是"挣来的"，不是"默认给的"**——用评估和线上表现（[evaluation/](../evaluation/00-评估与可观测学习总览.md)）证明它配得上更大的自主权和更高的风险动作，再逐步放开。配合**回滚机制**：出问题能快速退回上一版/降级。

---

## 2. 可靠性

Agent 依赖一堆会失败的东西（LLM API、工具、外部服务），生产要有韧性：

- **失败处理**（[agent-core/01](../agent-core/01-Agent循环与ReAct.md)/[02](../agent-core/02-工具使用ToolUse.md)）：工具/调用失败 → 重试（指数退避）、降级、把错误喂回让 Agent 自愈，而非崩溃。
- **降级（Fallback）**：关键依赖挂了有备选——备用模型/供应商、跳过非关键步骤、降级到更简单流程或人工。
- **超时与熔断**：每步设超时；某依赖持续失败则熔断，避免拖垮整体。
- **循环/预算上限**（[agent-core/01](../agent-core/01-Agent循环与ReAct.md)）：步数、token、成本、交接次数的硬上限——既防跑飞也防 DoW（[文档 03](03-权限隔离与最小权限.md)）。
- **确定性优先**：能用写死的工作流就别用自主决策（[orchestration/01](../orchestration/01-工作流编排五种模式.md)）——可靠性换灵活性要按需买。
- **上线前压测**：用模拟环境和压力测试找出性能瓶颈（[evaluation/04](../evaluation/04-评估数据集与CI.md) 的评估集 + 仿真）。

---

## 3. 成本治理 ⭐

> Agent 很烧钱：每个动作都是一次或多次 LLM 调用，链起几十步后 token 成本飙升。**把"每个工作流步骤的 token 消耗"当成一等公民指标来监控。**

降本手段（贯穿全课程，这里汇总）：
- **模型分级路由**：简单子任务（分类、路由、汇总）用**小而便宜**的模型，复杂推理才用强模型（[orchestration/06](../orchestration/06-生产实践与反模式.md)）。
- **缓存**：Prompt Caching 缓存重复前缀（系统提示/工具定义）、语义缓存复用相似问答、缓存中间推理结果（[context-engineering/04](../context-engineering/04-上下文管理技巧.md)、[rag/08](../rag/08-生产工程化与最佳实践.md)）。
- **上下文预算**：给每个（子）Agent 设上下文窗口预算，少塞 = 少 token（[context-engineering/02](../context-engineering/02-上下文工程基础.md)）。
- **减少步数/调用**：能简单别复杂、能一步别两步（[agent-core/06](../agent-core/06-模式选择与组合.md)）；能并行别串行省的是延迟不是钱，要分清。
- **监控每步 token**：把 token/步、成本/任务做成可观测指标（[evaluation/05](../evaluation/05-可观测性与追踪.md)），异常飙升及时告警。

---

## 4. 延迟治理

- **并行化**：无依赖的工具调用/检索并行跑（[orchestration/01](../orchestration/01-工作流编排五种模式.md) 的并行化；[rag/04](../rag/04-检索策略-混合检索与重排序.md) 的混合检索并行）。
- **流式输出（Streaming）**：边生成边返回，大幅降低**首字延迟（TTFT）**的体感。
- **跳过不必要步骤**：简单问题跳过 HyDE/重排/反思等重型步骤（[rag/05](../rag/05-查询理解-改写路由与转换.md)、Adaptive 思想）。
- **延迟预算 + 监控**：给各阶段设延迟预算，监控 p95/p99（[evaluation/05](../evaluation/05-可观测性与追踪.md)）。
- **快小模型做护栏**：护栏用蒸馏小模型，别让安全检查成为延迟大头（[文档 04](04-护栏与人类介入.md)）。

> 成本 vs 延迟有时冲突（并行降延迟但不降成本、缓存两者都降、强模型质量高但又贵又慢）——在**质量/成本/延迟**三角里按业务优先级权衡（[rag/00](../rag/00-RAG学习计划总览.md) 反复强调的三角）。

---

## 5. 扩展（Scaling）

- **离线/在线分离、无状态化**：把建库/索引等离线工作和在线服务分开；服务层尽量无状态（状态放 checkpoint/外部存储，[orchestration/03](../orchestration/03-状态管理与控制流.md)），便于水平扩展。
- **云原生架构**：从一开始就为弹性扩展设计（容器化、自动扩缩容）。预计到 2026，约 40% 企业应用会带任务专用 Agent——规模会来得很快。
- **限流与配额**：保护后端和钱包（[文档 03](03-权限隔离与最小权限.md)），按用户/租户限流。
- **异步与队列**：长任务异步化，用队列削峰，别阻塞在请求路径上。

---

## 6. 治理（Governance）⭐

规模化的成败往往不在技术而在治理：
- **访问控制**：谁能用这个 Agent、Agent 能访问什么（[文档 03](03-权限隔离与最小权限.md)）。
- **可审计性**：完整审计日志（[evaluation/05](../evaluation/05-可观测性与追踪.md) 的 trace）——谁、何时、做了什么、读了什么，可追溯、可合规。
- **护栏 + 回滚**：标准化的护栏（[文档 04](04-护栏与人类介入.md)）和快速回滚机制，是控制运营风险的支柱。
- **合规与数据驻留**：数据出不出境、是否被用于训练、PII 处理是否合规（[rag/08](../rag/08-生产工程化与最佳实践.md)）。
- **版本与变更管理**：Agent 的 prompt/工具/模型/模式都要版本化，变更走评估回归（[evaluation/04](../evaluation/04-评估数据集与CI.md)）。

---

## 7. 常见坑

- **一步到位全量全自主上线** → 不确定性 + 真实动作 = 事故。要渐进发布。
- **没有回滚机制** → 出问题退不回去。
- **不做失败处理/降级** → 依赖一抖整个 Agent 崩。
- **没有步数/预算上限** → 跑飞或被 DoW 烧钱。
- **不监控每步 token/成本** → 账单失控才发现。
- **所有子任务都用最强模型** → 成本爆炸。分级路由。
- **服务有状态、难扩展** → 规模一来就瓶颈。无状态 + checkpoint。
- **没有审计和治理** → 合规过不了、出事追不到。

---

## 8. 本章小结

- **渐进发布**：影子/试点 → 人工监督 → 逐步放权 → 全量自动；**自主权是挣来的**，配回滚机制。
- **可靠性**：失败重试/降级/喂回、超时熔断、步数预算上限、确定性优先、上线前压测。
- **成本治理**：把 token/步当一等指标；模型分级路由、缓存、上下文预算、减少步数、监控告警。
- **延迟治理**：并行化、流式输出、跳过不必要步骤、延迟预算 p95/p99、快小模型做护栏；在质量/成本/延迟三角里权衡。
- **扩展**：离线/在线分离、无状态+checkpoint、云原生、限流配额、异步队列。
- **治理决定规模化成败**：访问控制、可审计、护栏+回滚、合规、版本变更管理。
