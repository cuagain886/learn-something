## 2. Agent 上线总清单（Go-Live Checklist）⭐⭐

按主题分组。这是把全课程知识压缩成的"上线前逐项核对表"。

### A. 任务设计与架构（agent-core / orchestration）
- [ ] 确认**真的需要 Agent**——固定流程的部分用工作流/单次调用（[orchestration/01](../orchestration/01-工作流编排五种模式.md)、[agent-core/06](../agent-core/06-模式选择与组合.md)）。
- [ ] 从**单 Agent + ReAct + 好工具**起步，只在观察到失败时才加复杂模式（[agent-core/06](../agent-core/06-模式选择与组合.md)）。
- [ ] 多智能体仅在确需专长/隔离时用，默认从 Supervisor 拓扑起（[orchestration/02](../orchestration/02-多智能体架构与拓扑.md)）。
- [ ] **工具定义打磨到位**：描述清晰、Schema 严格、返回对模型友好（[agent-core/02](../agent-core/02-工具使用ToolUse.md)）。

### B. 循环控制（agent-core）
- [ ] 有**步数 / token / 成本 / 交接次数的硬上限**（没有步数上限的 Agent 不能上线）。
- [ ] 工具失败**喂回错误让 Agent 自愈**，配重试上限，不崩溃（[agent-core/01](../agent-core/01-Agent循环与ReAct.md)/[02](../agent-core/02-工具使用ToolUse.md)）。
- [ ] 防重复/防交接环、无进展检测、超限兜底。

### C. 知识与上下文（rag / context-engineering）
- [ ] RAG 用了**混合检索 + RRF + 重排**，检索质量经评估（[rag/04](../rag/04-检索策略-混合检索与重排序.md)/[07](../rag/07-RAG评估与可观测性.md)）。
- [ ] 上下文做了**策展和管理**（滑窗/摘要/卸载/缓存），不是"能塞就塞"（[context-engineering/02](../context-engineering/02-上下文工程基础.md)/[04](../context-engineering/04-上下文管理技巧.md)）。
- [ ] 长循环**重申目标**防漂移；记忆**按用户隔离**、会更新/遗忘（[context-engineering/03](../context-engineering/03-Agent记忆系统.md)）。

### D. 评估与可观测（evaluation）
- [ ] 有**评估集**（覆盖典型/边界/失败/对抗），评估**进 CI 做回归**（[evaluation/04](../evaluation/04-评估数据集与CI.md)）。
- [ ] 同时评**结果 + 轨迹**，做**步级评估**定位薄弱环节（[evaluation/02](../evaluation/02-Agent评估的维度与指标.md)）。
- [ ] 全链路 **trace**（记录每步实际进入上下文的内容），监控质量/成本/延迟，设**告警**（[evaluation/05](../evaluation/05-可观测性与追踪.md)/[06](../evaluation/06-线上持续评估与反模式.md)）。
- [ ] LLM 裁判**已校准**；有**用户反馈闭环**回流失败案例（[evaluation/03](../evaluation/03-评估方法与LLM裁判.md)/[06](../evaluation/06-线上持续评估与反模式.md)）。

### E. 安全与护栏（production）⭐
- [ ] 做过**威胁建模**（最坏后果倒推），对照 OWASP Agentic Top 10（[production/01](01-Agent安全威胁全景.md)）。
- [ ] **所有进入上下文的外部内容当不可信**，有注入检测 + 结构化隔离指令与数据（[production/02](02-Prompt注入与防御.md)）。
- [ ] **最小权限 + 权限隔离 + 沙箱**：被劫持也造不成严重后果；读不可信内容的组件无行动权（[production/03](03-权限隔离与最小权限.md)）。
- [ ] **输入/动作/输出护栏**到位；**高风险/不可逆动作有 HITL**（[production/04](04-护栏与人类介入.md)）。
- [ ] 数据按用户/租户隔离、防越权；PII 脱敏；出站地址白名单（[production/03](03-权限隔离与最小权限.md)、[rag/08](../rag/08-生产工程化与最佳实践.md)）。
- [ ] 防 DoW：资源/速率上限 + 配额。

### F. 部署与治理（production）
- [ ] **渐进发布**：试点/影子 → 人工监督 → 逐步放权 → 全量；有**回滚**机制（[production/05](05-生产部署与成本延迟治理.md)）。
- [ ] 可靠性：失败降级、超时熔断、上线前压测。
- [ ] 成本/延迟治理：模型分级、缓存、并行、流式、监控每步 token。
- [ ] 治理：访问控制、审计日志、合规/数据驻留、prompt/工具/模型**版本化 + 变更走评估回归**。

> 用法：上线前逐项过这张表，**任何一项"安全/循环控制"未达标都应阻止上线**（它们是硬门槛）。其余项按业务风险权衡。

## 3. 贯穿全课程的工程哲学（真正的内核）⭐⭐

清单会过时，但这几条思维方式不会。它们在每个专题反复出现，是这套课程真正想教给你的：

1. **从简单开始，失败驱动地加复杂度。**
   能单次调用就别上 RAG，能工作流就别上 Agent，能单 Agent 就别上多智能体，没遇到对应失败就别加对应模式。复杂度是为**已观察到的失败**买单，不是为臆想的需求。（[agent-core/06](../agent-core/06-模式选择与组合.md)、[orchestration/01](../orchestration/01-工作流编排五种模式.md)）

2. **没有评估就没有可迭代的系统。**
   量化是优化的前提。每个改动都用评估验证收益，否则只是玄学调参。（[evaluation/](../evaluation/00-评估与可观测学习总览.md)、贯穿所有专题）

3. **上下文是稀缺预算，不是仓库。**
   质量取决于"模型每一步看到了什么"。做减法、提信噪比，比堆信息重要。（[context-engineering/02](../context-engineering/02-上下文工程基础.md)）

4. **可观测是地基。**
   看不见内部，就既无法评估也无法调试。trace 是第一现场。（[evaluation/05](../evaluation/05-可观测性与追踪.md)）

5. **安全靠机制，不靠叮嘱；限后果，而非赌不犯错。**
   不能靠"在 prompt 里叮嘱模型别乱来"，要靠最小权限、护栏、HITL 等机制；与其赌模型不被骗，不如让它被骗了也没严重后果。（[production/02](02-Prompt注入与防御.md)/[03](03-权限隔离与最小权限.md)）

6. **在"质量/成本/延迟"三角里做工程。**
   几乎每个决策都是这三者的权衡，按业务优先级取舍。（[rag/00](../rag/00-RAG学习计划总览.md)、[production/05](05-生产部署与成本延迟治理.md)）

> 如果只记住一句话：**Agent 工程不是"让模型更聪明"，而是"用结构、评估、限权、可观测，把不确定的模型装进可靠的系统里"。**

## 6. 本章小结

- 全课程八阶段五专题，已覆盖从 LLM 应用基础到可靠 Agent 上线的完整路径。
- **上线总清单**按 任务设计 / 循环控制 / 知识上下文 / 评估可观测 / 安全护栏 / 部署治理 六组逐项核对；**安全与循环控制是硬门槛，未达标不上线**。
- 真正的内核是六条**工程哲学**：从简单开始、没评估没迭代、上下文是预算、可观测是地基、安全靠机制限后果、在三角里权衡。
- 一句话总结：**Agent 工程 = 用结构、评估、限权、可观测，把不确定的模型装进可靠的系统。**
