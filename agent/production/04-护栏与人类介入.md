# 04 · 护栏与人类介入

> 目标：掌握运行时的两道关键防线——**护栏（Guardrails）** 在每个请求上实时把关，**人类介入（HITL）** 在高风险动作前留人类闸门。以及主流护栏框架（LlamaFirewall 等）。

---

## 1. 护栏与 HITL 在防御纵深里的位置

[文档 02](02-Prompt注入与防御.md) 的防御纵深里：
- **护栏（Guardrails）** = 运行时审查层（③⑥⑦）：在内容进模型前、动作执行前、结果返回前，实时检查并拦截。
- **HITL（Human-in-the-Loop）** = 动作层（⑤）：高风险动作交给人确认。

两者的共同点：**它们是"运行时"的防线**（区别于 [文档 03](03-权限隔离与最小权限.md) 的"结构性"权限限制）。护栏是"自动的快速把关",HITL 是"人工的最终闸门"。

---

## 2. 护栏（Guardrails）：三个位置 ⭐

护栏是在 Agent 流程的关键位置插入的**实时检查器**，不合格就拦截/重试/降级。按位置分三类：

```
用户/外部内容 → [输入护栏] → Agent 推理/行动 → [动作护栏] → 执行
                                              → [输出护栏] → 返回用户
```

### 2.1 输入护栏（Input Guardrails）
进模型前检查输入和外部内容：
- **注入/越狱检测**：识别 prompt 注入、越狱话术（[文档 02](02-Prompt注入与防御.md)）。
- **不当内容过滤**：有害、违规内容。
- **PII 检测**：识别（并按需脱敏）个人敏感信息。

### 2.2 动作护栏（Action Guardrails）⭐
**Agent 决定调用工具后、真正执行前**检查这个动作：
- 是不是禁止动作（删库、对外发送到非白名单地址）？
- 是不是高风险动作（触发 HITL，见 §3）？
- 参数是否越界、是否操作了越权资源？
- 这是把 [evaluation/02](../evaluation/02-Agent评估的维度与指标.md) 的"动作安全"做成实时拦截。

### 2.3 输出护栏（Output Guardrails）
结果返回用户/触发下游前检查：
- 是否泄露敏感数据（PII、密钥、内部信息）？
- 是否有据（RAG 场景，对照检索内容，[rag/07](../rag/07-RAG评估与可观测性.md) 的 faithfulness）？
- 是否含有害/违规内容？
- 不合格 → 拦截/重写/降级到兜底回答。

> **护栏即实时评估**（[evaluation/06](../evaluation/06-线上持续评估与反模式.md)）：用快而便宜的评估器（含蒸馏小模型）在每个请求上把关。它和"离线评估"是同一套质量标准的两种应用——离线测、线上拦。

---

## 3. 人类介入（Human-in-the-Loop, HITL）⭐ 高风险动作的最终闸门

护栏能自动拦明显的，但**高风险、不可逆的动作不能完全交给自动判断**。

> **对高影响动作——金融交易、数据导出/删除、权限变更、对外发送——必须有人工审核确认后才真正执行。**

### 实现机制
靠编排的"中断→等待→恢复"（[orchestration/03](../orchestration/03-状态管理与控制流.md) 的 checkpoint + interrupt）：
```
Agent 决定执行高风险动作
   → 动作护栏识别为"高风险" → 中断，保存状态，请求人工审批
   → 人 批准/修改/拒绝
   → 批准则从断点恢复执行；拒绝则中止
```

### 怎么定"哪些动作要 HITL"
- **不可逆性**：能撤销的可放宽，不可逆的（删除、转账、发送）要 HITL。
- **影响范围**：影响大（生产数据、对外、涉钱）要 HITL。
- **置信度**：Agent 自身不确定时，升级给人。
- **权限敏感**：改权限、访问敏感数据要 HITL。

> 权衡：HITL 牺牲自动化换安全。**自主性越高、动作越危险，越要留人类闸门**——但别对低风险动作也要求确认（拖垮体验）。按风险分级。

---

## 4. 护栏框架与工具（2026）

不必全自己写，有现成框架：

### LlamaFirewall（Meta 开源）⭐
作为 AI Agent 的**最后一道防线**，三道护栏：
- **PromptGuard 2**：通用越狱检测器，SOTA 水平。
- **Agent Alignment Checks**：审查 Agent 推理链是否被注入带偏 / 偏离目标的"思维链审计员"（实验性，但对间接注入效果强）。
- **CodeShield**：在线静态分析引擎，拦截编码 Agent 生成的不安全/危险代码。
- 实测：组合使用使攻击成功率（ASR）**降低 90%（降到 1.75%）**，效用仅小幅下降。

### 云厂商 / 商业护栏
- **AWS Bedrock Guardrails**：PII 检测、内容过滤、prompt 攻击防护、图像支持。
- **Azure Content Safety**：多模态内容审核、越狱护盾（jailbreak shield）、**间接注入护盾**（indirect prompt injection shield）。
- **GraySwan Cygnal / Patronus AI / CrowdStrike** 等：注入检测、敏感数据脱敏、AIDR 策略、Agent 工具流检查等。

> 选型提示：护栏框架是**纵深的一层，不是唯一防线**（[文档 02](02-Prompt注入与防御.md)）。可组合多个（一条规则 fan-out 到多个护栏提供方，互补增强）。学习阶段可先了解 LlamaFirewall（开源可跑）。

## 5. 护栏的代价与权衡

- **延迟/成本**：每个请求多过几道检查，增加延迟和调用。用快/小模型做护栏（蒸馏裁判，[evaluation/03](../evaluation/03-评估方法与LLM裁判.md)）缓解。
- **误报（False Positive）**：护栏太严会拦正常请求，伤体验；太松则漏。要校准阈值（像校准 LLM 裁判一样，[evaluation/03](../evaluation/03-评估方法与LLM裁判.md)）。
- **HITL 拖慢**：人工确认引入延迟，只用于真高风险动作，按风险分级。
- **护栏会被绕过**：它是一层，不是终点。配合最小权限（[文档 03](03-权限隔离与最小权限.md)）才稳。

---

## 6. 常见坑

- **把护栏当唯一防线** → 会被绕过。它是纵深的一层，要配最小权限。
- **没有动作护栏** → Agent 执行危险动作前无人/无机制拦截。
- **高风险动作全自动、无 HITL** → 不可逆事故（删库、错转账）。
- **对所有动作都要 HITL** → 拖垮自动化和体验。按风险分级。
- **护栏阈值不校准** → 误报伤体验 或 漏报失效。
- **护栏用重模型、不优化** → 每请求延迟/成本飙升。用快/小模型。
- **不审计护栏拦截事件** → 看不到攻击趋势、无法改进。

---

## 7. 本章小结

- 护栏和 HITL 是**运行时防线**：护栏自动快速把关，HITL 人工最终闸门。
- **护栏三位置**：输入护栏（注入/越狱/PII）、**动作护栏（执行前拦危险动作）**、输出护栏（泄露/有据/有害）；本质是"护栏即实时评估"。
- **HITL 是高风险/不可逆动作的最终闸门**（交易/删除/权限/外发），靠编排的中断-恢复实现；按**不可逆性/影响/置信度/权限敏感**分级决定何时触发。
- 护栏框架：**LlamaFirewall（PromptGuard2 + Agent 对齐检查 + CodeShield，ASR 降 90%）**、AWS/Azure/商业护栏；可组合，是纵深的一层。
- 代价：延迟/成本/误报/拖慢——用快小模型、校准阈值、HITL 按风险分级缓解。
