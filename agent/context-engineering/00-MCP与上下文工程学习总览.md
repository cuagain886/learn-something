## 0. 这个专题讲什么，以及为什么它是 2026 的核心

[agent-core/](../agent-core/00-Agent核心学习总览.md) 解决了"Agent 怎么循环、怎么用工具、怎么规划反思"。但有个贯穿始终的隐患没展开：**Agent 的上下文窗口是有限的，而长任务会产生远超窗口的信息。**

> **一项 2025 企业分析发现：近 65% 的 Agent 失败，源于多步推理中的"上下文漂移"或"记忆丢失"。**

这让 **上下文工程（Context Engineering）成为 2026 年最被强调的生产学科**——从"写好一句 prompt"升级为"系统化地决定：在每一步，把哪些信息、以什么形式、塞进模型那个有限的窗口里"。

这个专题覆盖三件紧密相关的事：

```
            ┌─────────────────────────────────────────────────┐
            │              Agent 的上下文窗口（有限）            │
            │   系统提示 + 工具定义 + 历史 + 检索结果 + 记忆…    │
            └─────────────────────────────────────────────────┘
                 ↑供给               ↑策展              ↑持久化
            ┌─────────┐        ┌──────────────┐    ┌──────────┐
            │  MCP    │        │  上下文工程   │    │  记忆系统 │
            │工具/数据 │        │ 装什么/怎么压 │    │ 跨轮/跨会话│
            │标准接入 │        │              │    │ 记什么取什么│
            └─────────┘        └──────────────┘    └──────────┘
```

- **MCP**：工具和数据源**怎么标准化地连进 Agent**（供给侧）。
- **上下文工程**：在每一步**把哪些信息、怎么压缩后**放进窗口（策展侧）。
- **记忆系统**：哪些信息要**跨轮、跨会话持久化**，何时写入、何时取回（持久化侧）。

三者共同回答一个问题：**模型在每一步到底"看到"什么？** 这决定了 Agent 的可靠性上限。

## 1. 核心心智模型

### 1.1 上下文窗口是"预算"，不是"仓库" ⭐
不要把上下文窗口当成"能塞多少塞多少"的仓库。它是**稀缺、昂贵、且越满越不准**的预算：
- 塞得越多 → 越贵（按 token 计费）、越慢（首字延迟高）。
- 塞得越多 → **越容易"迷失在中间"**（模型对长上下文中间部分利用率下降）、越容易被无关信息干扰。

> 所以上下文工程的核心动作是**做减法和做策展**：在每一步只放"这一步真正需要的最少信息"，而不是把所有历史和检索结果一股脑倒进去。

### 1.2 MCP 是"标准化的供给"，不是"框架" ⭐
[agent-core/02](../agent-core/02-工具使用ToolUse.md) 讲了 function calling——但每接一个工具都要写定制胶水。**MCP 把"工具/数据源 ↔ Agent"的连接标准化**了（"AI 界的 USB-C"），让任意 Agent 用统一接口接入任意工具。它**不是** Agent 框架，是工具集成层，和 LangGraph 等编排框架**互补**。

### 1.3 记忆是"给上下文做的 RAG" ⭐
长期记忆的本质：把跨会话要记住的东西**存到外部**（向量库/图谱），需要时**检索回**当前上下文。这就是把 [rag/](../rag/00-RAG学习计划总览.md) 那套"存储-检索"用在了"Agent 的经历和知识"上。理解了 RAG，记忆系统就理解了一半。

## 2. 学习顺序

```
01 MCP            ← 工具/数据怎么标准化接入（承接 agent-core 的工具使用）
      ↓
02 上下文工程基础  ← 建立"窗口即预算"的核心认知，理解失败根源
      ↓
03 记忆系统        ← 跨轮/跨会话记什么、取什么（记忆即 RAG）
      ↓
04 上下文管理技巧  ← 具体手段：滑动窗口/摘要/卸载/压缩/缓存
      ↓
05 工程实践与反模式 ← 组合落地、评估、避坑
```

- **01（MCP）** 相对独立，是 agent-core 工具使用的自然延伸，可先学。
- **02-04 是一条线**：先懂"为什么上下文是命门"（02），再懂"什么该持久化"（03），再懂"具体怎么管"（04）。
- **05 收口**：把它们组合进真实 Agent，并避开反模式。

## 4. 本专题核心结论（剧透）

- **上下文窗口是稀缺预算**，上下文工程的核心是"策展 + 做减法"，不是"尽量多塞"。
- **65% 的 Agent 失败源于上下文漂移/记忆丢失**——这是可靠性的头号命门。
- **MCP = 工具/数据的标准化供给层**（host/client/server + Tools/Resources/Prompts 三原语），与编排框架互补，安全靠 host 侧的最小权限。
- **记忆 = 给上下文做 RAG**：短期（工作记忆）+ 长期（情景/语义/程序性），按需写入与检索。
- **管理技巧**：滑动窗口、分层摘要、记忆卸载、压缩、Prompt Caching——都是为了"在有限窗口里放对信息"。
