# 03 · Agent 记忆系统（Memory）

> 目标：掌握 Agent 的记忆——短期 vs 长期、三类记忆（情景/语义/程序性）、"记忆即 RAG"的本质、写入与检索策略，以及主流框架。

---

## 1. 为什么 Agent 需要记忆

上下文窗口是有限且短暂的（[文档 02](02-上下文工程基础.md)）。但 Agent 常常需要：
- **跨多轮**记住任务进展（这次会话里前面做了什么）。
- **跨多会话**记住用户偏好、历史事实（"用户上次说他用 Postgres"）。
- **积累经验**（"上次这么做失败了，这次换个方式"）。

这些都装不进、也不该长期占用上下文窗口。**记忆系统就是把这些信息存到窗口之外、需要时再取回**的机制。

> 核心类比：**人脑的工作记忆（当前在想的）很小，但长期记忆（存在脑子里、需要时回忆）很大。** Agent 也分这两层。

---

## 2. 短期记忆 vs 长期记忆 ⭐

### 2.1 短期记忆（Short-term / Working Memory）
- **就是当前上下文窗口里的内容**：当前对话/任务的近期消息、最近几步的思考-行动-观察。
- 受窗口大小限制，**会话结束就没了**（除非持久化）。
- 典型实现：保留最近 N 条原始消息（如 Zep 默认保留**最近 4~6 条原始消息**作为短期会话缓冲）。
- 管理手段：滑动窗口、摘要（[文档 04](04-上下文管理技巧.md)）。

### 2.2 长期记忆（Long-term Memory）
- **存在窗口之外**（向量库、图谱、数据库），**跨会话持久化**。
- 需要时**检索相关片段**回填到当前上下文。
- **这就是"给上下文做的 RAG"**（见第 4 节）。

```
            ┌──────────── 当前上下文窗口 ────────────┐
短期记忆 ──→ │ 最近几轮对话 + 最近几步 + 检索回来的长期记忆 │
            └────────────────────────▲───────────────┘
                                      │ 按需检索回填
长期记忆 ──→ ┌─────────────────────────┴──────────────┐
（窗口外）   │  向量库 / 知识图谱 / 数据库（持久化）      │
            │  存：用户偏好、历史事实、过往经历、学到的规则 │
            └────────────────────────────────────────┘
```

---

## 3. 三类长期记忆（2026 收敛的标准分类）⭐

2025-2026，Agent 生态收敛到一套**借鉴认知科学**的三层分类：

| 类型 | 存什么 | 例子 | 类比人脑 |
|------|--------|------|----------|
| **情景记忆（Episodic）** | 具体的过往交互/事件 | "用户上周让我帮他订过去北京的票" | 回忆"我经历过的事" |
| **语义记忆（Semantic）** | 事实、偏好、知识 | "用户偏好简洁回答""用户是后端工程师" | 知道"是什么" |
| **程序性记忆（Procedural）** | 学到的行为、规则、技能 | "处理这类工单要先查 X 再做 Y""上次这么做失败了" | 会做"怎么做" |

- **情景**：发生过什么（带时间/情境）。
- **语义**：稳定的事实和偏好（去掉了具体情境）。常由情景记忆**提炼/归纳**而来。
- **程序性**：怎么做事的经验/规则，让 Agent 越用越熟。

> 实践中很多系统先从**语义记忆（记住用户偏好/事实）**做起，它最直接、收益最明显。情景和程序性按需加。

## 4. 记忆的本质：给上下文做的 RAG ⭐

长期记忆的存储-检索循环，和 [rag/](../rag/00-RAG学习计划总览.md) 几乎一模一样：

```
写入（Encode）：  把要记的信息 → 嵌入 → 存进向量库/图谱（带元数据：时间、用户、类型）
检索（Recall）：  当前需要时 → 把当前情境/query 嵌入 → 检索最相关的记忆 → 回填上下文
```

所以 **[rag/](../rag/00-RAG学习计划总览.md) 的全部技巧都适用于记忆**：分块、嵌入、混合检索、重排、元数据过滤（按用户/时间筛）。理解了 RAG，记忆的检索侧就理解了。

**记忆比 RAG 多出来的难点**，主要在"写入"侧——见第 5 节。

---

## 5. 记忆的关键难题：写什么、何时写、何时取、何时忘 ⭐

RAG 的知识库是相对静态的；记忆是**动态生长**的，所以多了几个难题：

### 5.1 写什么（What to write）
不能把每句话都存（噪声爆炸、检索变差）。要**提炼**：从对话/经历里抽取"值得长期记住的"——稳定的偏好、关键事实、重要事件、有用的经验。常用 LLM 来做这个"提炼"动作（"从这段对话里提取应长期记住的用户事实"）。

### 5.2 何时写（When to write）
- 实时写（每轮后判断有无值得记的）vs 批量写（会话结束后总结）。
- 权衡：实时及时但贵，批量省钱但有延迟。

### 5.3 何时取（When/What to recall）
- 不是每步都检索记忆（贵、引噪声）。要判断"这一步需要回忆吗、回忆什么"。
- 检索回来要**重排、取最相关的少量**（呼应 [文档 02](02-上下文工程基础.md) 的"按需取少量"）。

### 5.4 何时更新/遗忘（Update & Forget）
- 事实会变（"用户从用 MySQL 改成了 Postgres"）——旧记忆要能**更新/失效**，否则检索到过时信息。
- 记忆要能"遗忘"无用/过期内容，否则越积越多、信噪比下降。
- **能追踪事实随时间变化**是高级记忆系统的关键能力（见 Zep 的时序图谱）。

## 6. 主流记忆框架（2026）

| 框架 | 架构路线 | 特点/适用 |
|------|----------|-----------|
| **Mem0** | 向量为主的语义召回 | 成熟、采用广；有开源(Apache 2.0)自托管 + 托管云服务。通用首选之一 |
| **Zep / Graphiti** | **时序知识图谱** + 双层记忆 | 显式区分短期会话缓冲(最近4~6条) 和长期上下文；**擅长追踪事实随时间变化** |
| **Letta（前 MemGPT）** | 自编辑记忆块（self-editing memory blocks） | 让 Agent 自己管理/编辑自己的记忆 |
| **LangGraph / LangMem** | 检查点持久化（checkpoint） | 与 LangGraph 编排深度集成，持久化 Agent 状态 |
| **LangChain ConversationBufferMemory** | 简单缓冲 | 入门/原型，保留对话历史 |

**选型提示：**
- **要追踪"事实随时间怎么变"** → Zep（时序图谱是它的真实优势）。
- **通用语义记忆、想要成熟方案** → Mem0。
- **已用 LangGraph 编排** → LangMem/checkpoint 顺手。
- **学习/原型** → 先用简单 buffer，理解了再上专门框架。

> 和 [rag/03](../rag/03-嵌入模型与向量数据库.md) 选向量库一样：先在自己场景小规模验证，别只看宣传。

## 7. 工程要点

- **记忆带元数据**：用户 ID、时间戳、记忆类型、来源——用于按用户隔离检索、按时间过滤、更新失效。（多租户场景必须按用户隔离记忆，否则串户泄露——呼应 [rag/08](../rag/08-生产工程化与最佳实践.md) 的权限。）
- **检索回来要重排 + 限量**：别把检索到的记忆全塞，按相关度取少量（[文档 02](02-上下文工程基础.md)）。
- **写入要去重/合并**：同一事实别存多份；新事实要能覆盖旧的。
- **评估记忆质量**：记忆系统也要评估——该记的有没有记住？该取的有没有取到？过时的有没有失效？（呼应 [rag/07](../rag/07-RAG评估与可观测性.md) 的检索评估。）

---

## 8. 常见坑

- **把所有对话原样全存** → 噪声爆炸、检索质量崩。要提炼。
- **记忆不更新/不遗忘** → 检索到过时事实，答错。
- **每步都检索记忆** → 贵且引入噪声。按需取。
- **检索到的记忆全塞进上下文** → 上下文膨胀、迷失在中间。重排限量。
- **多租户不按用户隔离记忆** → 串户、隐私泄露。元数据过滤必做。
- **不评估记忆** → 不知道记得对不对、取得准不准。

## 9. 本章小结

- 记忆 = 把窗口外的信息**持久化存储、按需取回**，分**短期（工作记忆=当前窗口内容）**和**长期（跨会话持久化）**。
- 长期记忆三类（认知科学分类）：**情景（发生过什么）、语义（稳定事实/偏好）、程序性（怎么做事的经验）**；通常先从语义记忆做起。
- **记忆的本质是给上下文做 RAG**——RAG 的分块/嵌入/混合检索/重排/元数据过滤全适用。
- 记忆比 RAG 多出的难点在**写入侧**：写什么（提炼）、何时写、何时取、何时更新/遗忘（尤其追踪事实随时间变化）。
- 框架：**Mem0（通用语义召回）、Zep（时序图谱、追踪变化）、Letta（自编辑）、LangMem（checkpoint）**；按需选型并自测。
- 工程上：记忆带元数据（按用户隔离）、检索重排限量、写入去重更新、记忆也要评估。

## 10. 检验清单

- [ ] 能区分短期记忆和长期记忆，并说出短期记忆就是当前上下文。
- [ ] 能说出三类长期记忆及各自存什么。
- [ ] 能解释"记忆即 RAG"，以及记忆比 RAG 多出的写入侧难题。
- [ ] 知道为什么"全存原始对话"是错的，正确做法是提炼。
- [ ] 能根据需求（如追踪事实变化）选出合适的记忆框架，并知道多租户要按用户隔离。
