# 05 · 工程实践与反模式

> 目标：把 MCP、上下文工程、记忆、管理技巧组合进真实 Agent，并系统化避坑。这是本专题的收口。

---

## 1. 把一切串起来：一个 Agent 一步里发生了什么

综合 [agent-core/](../agent-core/00-Agent核心学习总览.md) 和本专题，一个生产级 Agent 在**每一步**的上下文组装流程：

```
进入第 k 步：
  1. 固定前缀：系统提示 + 工具定义        → 走 Prompt Caching（文档04）
  2. 重申目标：把总目标放进来防漂移        → 文档02 原则
  3. 取记忆：  按当前情境检索长期记忆      → 文档03，重排限量
  4. 取知识：  需要外部知识则 RAG 检索      → rag/，重排取 top-k
  5. 组历史：  近期原文 + 较早摘要          → 文档04 滑动窗口+分层摘要
  6. 接工具：  当前可用工具（按需裁剪）     → MCP 接入(文档01)，工具多则裁剪
  → 组装成"最少够用、高信噪比"的上下文 → 调 LLM → 思考/行动（文档agent-core）
  → 大体积结果卸载到外部、提炼值得记的写入记忆 → 进入第 k+1 步
```

> 这张流程把整个学习地图串起来了：**MCP 供给工具/数据 → 上下文工程策展 → 记忆持久化 → 管理技巧控制体积 → agent-core 的循环消费它们。**

## 2. 失败模式与对应解法（诊断地图）

呼应 [文档 02](02-上下文工程基础.md)（65% 失败来自上下文），这是排查表：

| 失败现象 | 根因 | 解法 |
|----------|------|------|
| Agent 跑着跑着忘了目标 | 上下文漂移、目标被挤掉 | 固定头部保留目标 + 周期重申（文档02/04） |
| 多步后突然崩/截断 | 上下文爆窗口 | 滑动窗口、分层摘要、卸载（文档04） |
| 关键信息明明给了却没用 | 迷失在中间 | 关键信息放头/尾，减少噪声（文档02） |
| 答案被无关信息带偏 | 信噪比低、塞太多 | 做减法、重排限量（文档02/03） |
| 跨会话记不住用户偏好 | 没有长期记忆 | 加语义记忆（文档03） |
| 检索到过时的事实 | 记忆不更新/不遗忘 | 记忆更新失效机制（文档03） |
| 成本/延迟过高 | 重复前缀、上下文臃肿 | Prompt Caching、压缩（文档04） |
| 串户/隐私泄露 | 记忆没按用户隔离 | 元数据过滤按用户隔离（文档03） |

## 3. 评估：上下文/记忆也要量化（别凭感觉）

和 [rag/07](../rag/07-RAG评估与可观测性.md) 一脉相承——加了上下文工程/记忆，要用数据证明它有用：

- **记忆检索质量**：该记的有没有记住（召回）？取回的相不相关（精度）？过时的有没有失效？（复用 RAG 的 recall/precision 思路）
- **上下文有效性**：同一任务，不同上下文策略（滑窗 vs 摘要 vs 卸载）下的任务成功率对比。
- **端到端**：任务完成率、跑偏率、平均步数、成本/延迟。
- **可观测（trace）**：记录每一步**实际进入上下文的内容**——排查"模型为什么这么决策"时，必须能看到它当时到底看到了什么。这是 [INDEX 阶段6](../INDEX.md) 的核心。

> 没有 trace 就无法定位上下文问题——你根本不知道模型那一步看到了什么。**"实际进入上下文的内容"是 Agent 调试的第一现场。**

## 4. 安全要点（本专题相关，详见 INDEX 阶段7）

- **MCP 最小权限**（[文档 01](01-MCP模型上下文协议.md)）：server 配最小权限、只读过滤，安全在 host/server 侧用代码强制，不靠系统提示。
- **记忆按用户隔离**（[文档 03](03-Agent记忆系统.md)）：多租户必做，防串户泄露。
- **警惕进入上下文的外部内容**：RAG 检索结果、MCP resource、工具返回都可能含恶意指令（间接 prompt 注入）。用结构化分隔（标签包裹"资料"和"指令"），降低注入风险（[文档 02](02-上下文工程基础.md) 的"结构化区分"原则同时也是安全措施）。
- **记忆投毒（Memory Poisoning）**：攻击者诱导 Agent 把恶意信息写进长期记忆，污染后续所有会话。写入记忆的内容也要审视，不能照单全收。

## 5. 反模式（明确避免）

| 反模式 | 为什么错 | 正解 |
|--------|----------|------|
| **能塞就塞、上下文当仓库** | 又贵又慢、迷失在中间、被噪声带偏 | 最少够用 + 高信噪比（文档02） |
| **历史原样线性堆积** | 几步就爆窗口 | 滑窗 + 分层摘要 + 卸载（文档04） |
| **把全部对话存进长期记忆** | 噪声爆炸、检索质量崩 | 提炼后再存（文档03） |
| **每步都全量检索记忆+知识** | 贵、引噪声、膨胀 | 按需取、重排限量 |
| **Prompt Caching 不当**（变化内容放前面） | 缓存永不命中 | 固定内容放前部（文档04） |
| **靠系统提示做 MCP 安全** | 被注入绕过 | host/server 侧代码强制最小权限（文档01） |
| **记忆不按用户隔离** | 串户泄露 | 元数据过滤（文档03） |
| **不留 trace、不评估上下文策略** | 出问题抓瞎、凭感觉调 | trace + 评估（本章 §3） |
| **把 MCP 当编排框架** | 概念错位 | MCP 只管接入，编排用框架（文档01） |
| **盲目追大窗口忽视信噪比** | 塞满更糟 | 大窗口也要策展（文档02） |

## 6. 落地推进顺序（务实路线）

```
1. 先把 agent-core 的单 Agent + ReAct + 好工具跑通（前置）
2. 加基础上下文管理：固定头部(目标)+滑动尾部，控制历史膨胀
3. 工具接入标准化：把工具改成 MCP server 暴露（文档01）
4. 加语义记忆：记住用户偏好/关键事实，按用户隔离（文档03）
5. 长任务加分层摘要 / 记忆卸载（文档04）
6. 成本优化：Prompt Caching + 必要时压缩（文档04）
7. 加 trace + 评估：量化每项改动的收益（本章§3）
8. 安全加固：MCP最小权限、记忆隔离、防注入/投毒（本章§4 / INDEX阶段7）
```

> 同样遵循 [agent-core/06](../agent-core/06-模式选择与组合.md) 的纪律：**从简单起步，观察到失败（上下文漂移、记不住、太贵）再加对应手段，每步用评估验证。**

## 7. 本章小结

- 一个 Agent 每步的上下文组装：**缓存固定前缀 → 重申目标 → 取记忆 → 取知识 → 组历史(近原文+远摘要) → 接工具**，目标是"最少够用、高信噪比"。
- **失败诊断地图**把"现象→根因→解法"对应起来，多数 Agent 问题能在这里定位。
- 上下文/记忆**也要评估和 trace**：尤其要记录"每步实际进入上下文的内容"——这是调试第一现场。
- 安全：MCP 最小权限、记忆按用户隔离、防间接注入与记忆投毒。
- 牢记反模式：当仓库塞、历史堆积、全量存记忆、缓存放错、靠提示做安全、不评估。
- 落地按"跑通单 Agent → 上下文管理 → MCP → 记忆 → 长任务压缩 → 缓存 → 评估 → 安全"推进，失败驱动、评估验证。
