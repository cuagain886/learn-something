## 1. 核心心智模型

### 1.1 工作流（Workflow）vs 智能体（Agent）——先分清 ⭐
（[INDEX](../INDEX.md) 和 [agent-core/00](../agent-core/00-Agent核心学习总览.md) 强调过，这里是本专题的起点）

> - **工作流（Workflow）**：LLM 和工具被**预先写死的代码路径**编排——流程是你定的，可预测、可控、可靠。
> - **智能体（Agent）**：LLM **自己动态决定**流程和工具用法——灵活，但不确定、难调试。

"编排"这个词同时覆盖两者：**编排既可以是写死的工作流，也可以是动态的多 Agent。** 本专题 [文档 01](01-工作流编排五种模式.md) 先讲可控的工作流模式（很多任务用它就够，比多智能体稳得多），[文档 02](02-多智能体架构与拓扑.md) 起再讲动态多 Agent。

### 1.2 编排的本质是"控制流 + 状态"⭐
不管是工作流还是多智能体，编排要解决两件事：
- **控制流（Control Flow）**：下一步交给谁？什么时候结束？怎么分支/循环/回退？
- **状态（State）**：信息在各个节点/Agent 之间怎么传递、共享、持久化？

> 现代编排框架（以 **LangGraph** 为代表）把这两件事抽象成**图（Graph）**：节点是步骤/Agent，边是控制流，状态在图里流转。理解了"图模型"，就理解了现代编排的核心（[文档 03](03-状态管理与控制流.md)）。

### 1.3 自主性越高，越要靠"结构"兜底
多智能体把单 Agent 的不确定性乘以 N。所以工程上反而要用**结构化的编排**（明确的状态、可控的交接、checkpoint、人类介入点）来约束这种不确定性——**用工程结构换可靠性**。

## 4. 本专题核心结论（剧透）

- **"编排"覆盖工作流（写死、可控）和多智能体（动态、灵活）两端**；能用工作流就别上多智能体。
- **Anthropic 五种工作流模式**（链式/路由/并行/编排者-工人/评估优化）是经过验证的工程模板，先用它们。
- 多智能体拓扑里，**Supervisor（有中央协调，准）vs Swarm（直接交接，快）** 是最核心的一对取舍。
- 编排的本质 = **控制流 + 状态**，现代框架用**图模型**统一表达；**Checkpoint 持久化和人类介入（HITL）** 是生产必备。
- **A2A 协议**让跨框架/跨厂商的 Agent 能互相通信协作（2026 标准，已入 Linux Foundation）。
- 框架选型：**LangGraph（可控、生产级）、CrewAI（快速原型）、OpenAI Agents SDK / Claude Agent SDK / Google ADK** 各有侧重。
- 多智能体的可靠性靠**结构化编排 + 强可观测**兜底；成本/延迟/错误传播是主要代价。
