# 03 · 状态管理与控制流

> 目标：掌握编排的核心机制——用**图（Graph）**表达控制流、管理**状态**、用 **Checkpoint** 持久化、插入**人类介入（HITL）**、支持循环/分支/中断恢复。这是现代编排框架（以 LangGraph 为代表）的精髓。

---

## 1. 编排的两件核心事：控制流 + 状态

[文档 00](00-多智能体与编排学习总览.md) 提过：编排本质是解决两件事。

- **控制流（Control Flow）**：下一步交给谁？何时结束？怎么分支、循环、回退？
- **状态（State）**：信息在各节点/Agent 间怎么传递、共享、持久化？

朴素做法（自己写 if/else + 全局变量传参）在简单场景能用，但一旦有**循环、分支、多 Agent、需要暂停恢复、需要人工介入**，就会乱成一团。现代框架用**图模型**统一解决。

---

## 2. 图模型（Graph）：现代编排的核心抽象 ⭐

以 **LangGraph** 为代表，把编排建模成一张**有向图（状态机）**：

```
        ┌──────────────────────────────────────┐
        │            共享状态 State              │  ← 所有节点读写的"中央数据"
        └──────────────────────────────────────┘
              ▲          ▲           ▲
        ┌─────┴───┐  ┌───┴────┐  ┌───┴────┐
        │ 节点Node │→ │ 节点Node│→ │ 节点Node│   ← 节点=步骤/Agent/工具
        └─────────┘  └────┬───┘  └────────┘
                          │ 条件边（根据状态决定走向）
                    ┌─────┴─────┐
                    ▼           ▼
                 节点X         节点Y
```

三个核心概念：

- **节点（Node）**：一个执行单元——可以是一次 LLM 调用、一个工具、一个完整的子 Agent。节点读取状态、做事、更新状态。
- **边（Edge）**：控制流。
  - **普通边**：A 做完固定走 B。
  - **条件边（Conditional Edge）**⭐：根据**当前状态**决定下一步走哪个节点——这就是路由、分支的实现。
  - **循环边**：边可以指回之前的节点，形成**循环**（这正是 [agent-core/01](../agent-core/01-Agent循环与ReAct.md) Agent 循环的图表达）。
- **状态（State）**：一个贯穿全图的共享数据结构（消息历史、中间结果、当前激活 Agent 等）。节点通过"更新状态"来传递信息，不用手动传参。

> 为什么图模型强？因为它把"循环、分支、并行、多 Agent 交接"都统一成"节点 + 边 + 状态"，可显式定义、可视化、可控制。Agent 的不确定循环被装进了一个**可控的结构**里——这正是 [文档 00](00-多智能体与编排学习总览.md) 说的"用工程结构换可靠性"。

---

## 3. 状态管理细节

### 3.1 状态里放什么
- 对话/消息历史、各步中间结果、任务进度、**当前激活的 Agent**（多 Agent 必备）、计数器（用于步数上限）等。
- 状态设计要呼应 [context-engineering/](../context-engineering/00-MCP与上下文工程学习总览.md)：不是什么都往状态里堆，注意上下文预算。

### 3.2 状态更新（Reducer）
多个节点（尤其并行节点）可能同时更新状态，框架用 **reducer** 定义"怎么合并更新"（如消息列表是**追加**，某个标志是**覆盖**）。理解这点能避免并行时状态相互覆盖。

---

## 4. Checkpoint（检查点 / 持久化）⭐ 生产必备

**Checkpointer 在每一步把状态快照保存下来。** 这带来几个关键能力：

| 能力 | 说明 |
|------|------|
| **多轮记忆** | 跨多轮对话保持状态——这就是 Agent 的**短期记忆**（[context-engineering/03](../context-engineering/03-Agent记忆系统.md)）。**Swarm 必须配 checkpoint**，否则会"忘了"上次激活哪个 Agent、丢历史（[文档 02](02-多智能体架构与拓扑.md)）。 |
| **暂停与恢复** | 可在任意节点暂停、之后从快照恢复执行——人类介入、长任务跨时段都靠它。 |
| **容错** | 某步崩溃后，可从最近 checkpoint 恢复，不必从头重跑（省钱省时）。 |
| **时间旅行（Time Travel）** | 回退到历史状态、修改后重跑——强大的调试手段。 |

> 一句话：**checkpoint 把"易失的内存状态"变成"可持久化、可恢复、可回溯"的状态**。生产级编排几乎一定要开。

---

## 5. 人类介入（Human-in-the-Loop, HITL）⭐

很多场景不能让 Agent 全自动跑到底，需要在关键点**暂停、等人确认/修改、再继续**。

```
…执行 → 到达高风险节点 → 中断(interrupt)、保存checkpoint → 等人审批
                                                          │
                              人批准/修改 ──→ 从checkpoint恢复继续
```

- **典型场景**：高风险动作前确认（转账、删数据、对外发送——[INDEX 阶段7](../INDEX.md)）、低置信时让人决策、人工修正中间结果。
- **实现**：靠 checkpoint 支持"中断（interrupt）→ 持久化 → 恢复（resume）"。LangGraph 等开箱支持。
- **价值**：HITL 是把高自主 Agent 安全地用于生产的关键护栏之一——**自主性越高，越需要在关键节点留人类闸门**。

---

## 6. 控制流模式：循环、分支、并行、中止

图模型让这些都可显式表达：

- **循环（Loop）**：边指回前节点，配合**状态里的计数器/条件**实现"重试""迭代直到满意"。**务必有退出条件 + 步数上限**（[agent-core/01](../agent-core/01-Agent循环与ReAct.md) 的"没有步数上限的 Agent 不能上线"在图里同样适用——用条件边检查计数器强制退出）。
- **分支（Branch）**：条件边根据状态走不同路径（路由的实现）。
- **并行（Parallel / Fan-out）**：从一个节点分出多条边并行执行，再汇聚（fan-in），配 reducer 合并结果（[文档 01](01-工作流编排五种模式.md) 的并行化）。
- **中止/回退**：条件边检测到失败或超限，导向"终止节点"或"兜底节点"。

---

## 7. 工程要点

- **状态结构先设计好**：它是整个编排的"数据契约"，中途改很痛。明确每个字段、谁写谁读、怎么合并。
- **必开 checkpoint**（生产）：拿到多轮记忆、恢复、容错、调试。
- **循环必设退出条件 + 计数上限**：图里用条件边强制，防跑飞。
- **高风险节点插 HITL**：用 interrupt/resume。
- **可观测**：记录每个节点的输入/输出/状态变化（trace）——多 Agent 调试全靠它（[文档 06](06-生产实践与反模式.md)、[INDEX 阶段6](../INDEX.md)）。

---

## 8. 常见坑

- **不用框架、手写 if/else + 全局变量** → 一旦有循环/分支/多 Agent/恢复就失控。
- **不开 checkpoint** → 没有多轮记忆、不能恢复、崩了从头来、Swarm 忘状态。
- **循环没有退出条件/计数上限** → 无限循环烧钱。
- **状态结构没设计好/中途乱改** → 节点间数据契约崩坏。
- **并行更新不懂 reducer** → 状态互相覆盖、结果丢失。
- **高风险全自动、不留 HITL** → 不可逆事故。
- **状态里堆太多** → 上下文膨胀（违反 [context-engineering/02](../context-engineering/02-上下文工程基础.md)）。

---

## 9. 本章小结

- 编排的核心 = **控制流 + 状态**；现代框架（LangGraph）用**图模型**统一表达：**节点（执行单元）+ 边（含条件边/循环边）+ 共享状态**。
- 图模型把循环、分支、并行、多 Agent 交接装进**可控结构**，用工程结构换可靠性。
- **Checkpoint（持久化）是生产必备**：带来多轮记忆、暂停恢复、容错、时间旅行调试；Swarm 必须配。
- **HITL（人类介入）** 靠 checkpoint 的中断/恢复实现，是高自主 Agent 的关键安全闸门。
- 循环必须有**退出条件 + 步数上限**（图里用条件边强制）；并行更新要懂 reducer。
- 状态结构是"数据契约"，要先设计好、别乱堆。
