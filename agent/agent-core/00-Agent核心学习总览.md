## 1. 一个贯穿全程的心智模型

### 1.1 Agent 的本质：循环 + 自主决策

> 普通 LLM 调用是"一问一答"；**Agent 是把 LLM 放进一个循环里，让它反复"思考下一步→采取行动→观察结果"，由它自己决定何时停止。**

```
普通调用：   输入 ──→ LLM ──→ 输出（结束）

Agent：      目标 ──→ ┌─────────────────────────────┐
                      │  LLM 思考"下一步做什么"       │
                      │      ↓                        │
                      │  采取行动（调用工具）          │ ←─ 循环
                      │      ↓                        │
                      │  观察结果，喂回 LLM            │
                      └──────────┬──────────────────┘
                                 ↓ （LLM 判断"完成了"）
                              最终答案
```

这个循环就是 Agent 的"引擎"。[文档 01](01-Agent循环与ReAct.md) 会把它拆到最细。

### 1.2 设计模式是"循环的不同玩法"

本专题的几个模式，本质都是在改造这个基础循环：

| 模式 | 对循环做了什么 |
|------|----------------|
| **ReAct** | 最基础的循环：思考与行动交替 |
| **Tool Use** | 循环里"行动"的具体实现——调用外部工具 |
| **Reflection** | 在循环里加一步"自我评估→修订" |
| **Planning** | 循环开始前/中途先产出一个"计划"，按计划走 |
| **Multi-Agent** | 把循环拆给多个专职 Agent，各跑各的再协作 |

### 1.3 最重要的一条纪律：从简单开始 ⭐

这是贯穿整个专题、也是 2026 业界（尤其 Anthropic）反复强调的：

> **先用 ReAct + 好工具。** 这能解决现实中大多数任务。
> 其它模式（规划、反思、多智能体）都是为**特定失败模式**准备的：
> - 成本太高 → ReWOO / 减少 LLM 调用
> - 计划太复杂、步骤多 → Plan-and-Execute
> - 正确性不够 → Reflection / Reflexion
> - 单 Agent 上下文/角色不够 → Multi-Agent
>
> **如果你还没遇到这些失败，就别加对应的复杂度。让失败来告诉你何时"毕业"到更复杂的模式。**

[文档 06](06-模式选择与组合.md) 会把这条纪律变成可操作的决策树。

## 2. 学习顺序建议

```
01 Agent循环与ReAct  ← 必读，地基。先彻底搞懂基础循环
        ↓
02 工具使用 ToolUse   ← 必读，循环的"手脚"。亲手实现一遍完整回合
        ↓
03 反思 / 04 规划 / 05 多智能体  ← 三种进阶模式，理解各自解决的失败
        ↓

```

- **前两篇（01、02）是地基，必须动手实现。** 一个能调用工具的 ReAct 循环，就是你的第一个真正的 Agent。
- **中间三篇（03、04、05）按需深入**，理解它们各自针对的失败模式即可，不必全部立刻上手。
- **最后一篇（06）是决策收口**，帮你避免"为了用而用"的过度工程。

## 4. 动手项目（边学边做）

学完本专题，目标是搭出这样一个 Agent：

```
一个"研究助手" Agent：
  - 工具：网络搜索、网页抓取、（可选）RAG 检索本地知识库、计算器
  - 循环：ReAct —— 思考要查什么 → 搜索 → 读结果 → 判断够不够 → 不够再搜 → 汇总
  - 进阶：给最终报告加一轮 Reflection（自我评估是否完整、有无遗漏）
  - 控制：设最大步数上限、处理工具失败、防止重复搜同样的东西
```

这个项目会把 01-04 的知识全用上，是检验是否真懂的最好方式。

## 5. 本专题的核心结论（剧透）

- **Agent = LLM + 工具 + 循环 + 自主决策**；循环是引擎，工具是手脚。
- **ReAct 是默认起点**，单 Agent + ReAct + 好工具搞定大多数任务。
- **工具设计的质量 ≈ Agent 能力的上限**：工具描述清晰、Schema 严格、错误能被模型理解，Agent 才靠谱。
- **进阶模式是"失败驱动"的**：先遇到失败，再上对应模式，别提前过度工程。
- **循环控制（停止条件、步数上限、防循环）是工程重点**，否则 Agent 会无限循环、烧钱、跑飞。
