# 01 · 切片 slice 底层原理 ⭐⭐⭐

> 切片是 Go 面试**出现频率最高**的数据结构题，几乎逢面必考。核心就一句话：
> **切片是底层数组的一个"视图"，它本身是个轻量结构体，按值传递。**

---

## 1. 底层结构：切片只是 3 个字段

切片在运行时的真身（`runtime/slice.go`）：

```go
type slice struct {
    array unsafe.Pointer // 指向底层数组的指针（第一个元素的地址）
    len   int            // 长度：当前有几个元素，决定 s[i] 越界边界
    cap   int            // 容量：底层数组从 array 起还能放几个，决定何时扩容
}
```

所以一个切片变量在 64 位机器上占 **24 字节**（指针 8 + len 8 + cap 8），和它装了 3 个还是 300 万个元素无关。

```
s := []int{10, 20, 30}        底层数组（在别处）
┌──────────────┐              ┌────┬────┬────┐
│ array ───────┼─────────────▶│ 10 │ 20 │ 30 │
│ len   = 3    │              └────┴────┴────┘
│ cap   = 3    │
└──────────────┘
```

**面试要点**：`len` 和 `cap` 的区别——`len` 是"能访问到的"，`cap` 是"底层数组总共有的"。`s[len:cap]` 那段内存是存在的但你访问不到，`append` 会用它。

---

## 2. 扩容机制 ⭐（最高频考点）

`append` 时如果 `len == cap`，就触发扩容：**分配一块更大的新数组，把旧数据拷贝过去**，原数组若没人引用则被 GC 回收。

### 扩容倍数规则（Go 1.18+）

```go
// runtime/slice.go growslice 的核心逻辑（简化）
newcap := oldcap
if oldcap < 256 {
    newcap = oldcap * 2          // 小切片：翻倍
} else {
    // 大切片：每次约 1.25 倍，平滑增长，避免内存浪费
    for newcap < needed {
        newcap += (newcap + 3*256) / 4
    }
}
```

> ⚠️ **版本差异**：Go 1.18 之前的阈值是 **1024**（小于 1024 翻倍，否则 1.25 倍）；1.18 起改为 **256**，且大切片增长公式更平滑。面试答"小于 1024 翻倍"在新版本是不准确的，最好两个版本都提一句。

### 实测扩容过程

```go
s := make([]int, 0)
oldCap := cap(s)
for i := 0; i < 10; i++ {
    s = append(s, i)
    if cap(s) != oldCap {
        fmt.Printf("len=%d 时扩容: cap %d -> %d\n", len(s), oldCap, cap(s))
        oldCap = cap(s)
    }
}
// 输出（cap 序列）：0 -> 1 -> 2 -> 4 -> 8 -> 16 ...
```

> ⚠️ 实际容量还会经过**内存对齐**（roundupsize，对齐到 size class），所以有时不是严格的 2 倍。比如 `[]int` 从 cap 4 扩容理论上 8，但因对齐可能直接给更大值。面试时提到"还要考虑内存对齐到 size class"是加分项（见 [08 内存分配](08_memory_alloc_escape.md)）。

## 3. ⭐⭐ 灵魂拷问：append 为什么有时影响外部、有时不影响？

这是**最经典的 slice 面试题**，本质是"扩容与否决定了是否还共享底层数组"。

```go
func modify(s []int) {
    s[0] = 100        // ① 修改元素：永远影响外部（共享底层数组）
    s = append(s, 1)  // ② append：影不影响外部，取决于是否扩容
}

func main() {
    a := make([]int, 3, 3) // len=cap=3，已满
    modify(a)
    fmt.Println(a) // [100 0 0] —— ① 生效了，② 没生效
}
```

**逐步分析**：
- 切片**按值传递**：`modify` 拿到的 `s` 是 `a` 的拷贝，但拷贝的 `array` 指针指向**同一个底层数组**。
- `s[0] = 100`：通过共享指针改底层数组 → **外部 `a` 看得到**。
- `s = append(s, 1)`：此时 `len==cap==3`，**触发扩容** → `s` 指向了新数组，`a` 还指向旧数组 → 外部 `a` **看不到**新增的元素，连 `len` 也没变（`a` 的 len 还是 3）。

**对比：如果容量够，append 会"写穿"到共享数组** ⚠️

```go
func main() {
    a := make([]int, 3, 5) // cap=5，还有空位
    b := a[:2]             // b 与 a 共享底层数组，len(b)=2 cap(b)=5
    b = append(b, 999)     // 容量够，不扩容，直接写底层数组的第 3 格
    fmt.Println(a)         // [0 0 999] —— a 被 b 的 append 改了！⚠️
}
```

**标准答法**：
> append 后是否影响原切片，取决于**有没有发生扩容**。没扩容时新旧切片共享底层数组，写操作互相可见；一旦扩容，append 返回的切片指向新数组，与原切片脱钩。所以**永远要接收 append 的返回值** `s = append(s, x)`，不能假设它原地修改。

## 4. ⚠️ 三大经典陷阱

### 陷阱 1：切片截取后共享底层数组，意外篡改

```go
base := []int{1, 2, 3, 4, 5}
sub := base[1:3]   // [2 3]，但 cap(sub)=4（到底层数组末尾）
sub[0] = 999
fmt.Println(base)  // [1 999 3 4 5] —— base 被改了！
```

**解法**：用**完整切片表达式**限制容量 `base[1:3:3]`（low:high:max），让后续 append 必然扩容；或 `slices.Clone` / `copy` 出独立副本。

### 陷阱 2：大数组被小切片"钉住"无法回收（内存泄漏）

```go
func readFirstLine(file []byte) []byte {
    return file[:100]  // ⚠️ 返回的切片仍引用整个 file 底层数组！
}                      // 哪怕 file 有 1GB，这 100 字节也让整个 1GB 无法 GC
```

**解法**：`return append([]byte(nil), file[:100]...)` 或 `slices.Clone` 拷贝出真正独立的小切片。

### 陷阱 3：range 时修改切片 / 循环变量取址

```go
s := []int{1, 2, 3}
for _, v := range s {
    s = append(s, v) // range 在开始时就确定了遍历 3 次，不会无限循环
}
// s == [1 2 3 1 2 3]，range 遍历的是开始时的快照长度
```

## 5. 其他高频细节

**nil 切片 vs 空切片**：
```go
var a []int          // nil 切片：a == nil 为 true，array 指针为 nil
b := []int{}         // 空切片：b == nil 为 false，array 指向一个特殊地址
c := make([]int, 0)  // 同空切片
// 三者 len 都是 0，都能安全 append/range。
// ⚠️ JSON 序列化有别：nil -> null，空切片 -> []。API 设计要注意。
```
**惯例**：声明用 `var s []T`（nil 切片）最干净，不要写 `s := []T{}`。

**copy 的返回值**：`copy(dst, src)` 返回**实际拷贝的元素个数 = min(len(dst), len(src))**。
```go
dst := make([]int, 2)
n := copy(dst, []int{1, 2, 3, 4}) // n=2，dst=[1 2]，只拷了 2 个
```

**切片作为函数参数高效**：传切片只拷贝 24 字节的头，不拷贝底层数据——所以 Go 里传切片不需要传指针（除非要在函数内改变切片本身的 len/cap 让外部可见，才传 `*[]T`）。

## 6. 面试速答清单

| 问题 | 一句话答案 |
|------|-----------|
| 切片底层结构？ | 指向底层数组的指针 + len + cap，3 个字段 24 字节 |
| 扩容规则？ | <256 翻倍，≥256 约 1.25 倍递增，再按 size class 内存对齐（1.18 前阈值是 1024） |
| append 一定原地吗？ | 不一定，满了就扩容换新数组，所以必须 `s = append(...)` |
| 怎么避免共享数组的坑？ | 完整切片表达式 `s[a:b:b]` 限容，或 `slices.Clone` 深拷贝 |
| 为什么传切片不用传指针？ | 切片头本身很小，且内含指针能改到底层数据；只有要改 len/cap 才传 `*[]T` |
| nil 切片能 append 吗？ | 能，`append(nil, x)` 会分配新数组，完全安全 |

---

## 一句话总结

> **切片 = 底层数组的视图（指针+len+cap），按值传递头部、共享底层数据；扩容会换数组导致脱钩，所以永远 `s = append(s, x)`，需要独立副本就 `slices.Clone`。**
